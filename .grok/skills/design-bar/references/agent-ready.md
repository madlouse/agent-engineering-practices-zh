# 对 Agent 友好：让 AI 访问时拿得到高质量数据

替人读网页的不只是人：搜索和问答产品的爬虫、替用户取页的工具、在浏览器里操作的 Agent。它们大多不执行脚本、看不到版式，只拿到 HTML 和几份约定的文件。数据质量高，指的是它们拿到的内容完整、准确、带出处和日期，而且不用猜。

分工：`ux-canon.md` 第 4 节讲产品里的 Agent 替人做事时界面怎么设计；项目的质量规则定这个产品的门槛。本文件讲一个对外的站点**做什么**、**设计阶段定什么**、**怎么查**。检查脚本是 `scripts/check_agent_ready.py`。

## 一条原则

**所有机器可读件都由同一份内容数据生成，不手写第二份。** 页面、结构化数据、订阅源、站点地图、`llms.txt`、Markdown 和 JSON 都从同一个来源出。手写的第二份迟早和页面对不上，而 Agent 分不出哪份是对的。

## 做什么（按价值排序）

每条后面是它为什么让数据质量更高。哪些是检查脚本的必须项，见最后「怎么查」：必须项只管 Agent 取不取得到内容、取到的对不对，范围比这张清单窄。

1. **不执行脚本也读得到正文和元信息。** 多数爬虫和取页工具只拿原始 HTML。正文靠脚本渲染，它们拿到的是空壳，或者只有导航。
2. **语义化的 HTML 和可读名称。** 一页一个 `h1`、标题不跳级、`header` / `nav` / `main` / `footer` 齐全；可点的都是原生的 `a[href]`、`button`，有可读名称；图片有 `alt`；日期用 `<time datetime>`。Agent 靠结构切分内容、靠名称找控件；`div` 上挂的点击它看不到。
3. **每页说清自己是谁。** `title`、描述、`canonical`（绝对地址）、`<html lang>`，多语言的再加 `hreflang`。同一内容有几个地址时，`canonical` 让它们被当成一篇，不被重复收录或引到错的版本。
4. **找得到。** `robots.txt` 不误挡，写明站点地图；`sitemap.xml` 列全公开页面和更新日期。
5. **每条内容的元信息齐全，页面上看得到，机器也读得到。** 作者、发布和更新日期、出处、授权、语言、适用范围。转述时带得上出处和日期，旧结论不会被当成新结论；授权写明了，Agent 知道能不能引用、怎么引用。
6. **结构化数据（JSON-LD）。** 文章用 `Article` / `BlogPosting`，站点用 `WebSite`，带作者、`datePublished`、`dateModified`、`inLanguage`。字段有确定的含义，不用从版式里猜哪个是日期、哪个是作者。
7. **每篇正文有 Markdown 地址**，页面用 `<link rel="alternate" type="text/markdown" href="…">` 指过去。Agent 不用从 HTML 里剥正文，剥的过程会丢表格、代码块和脚注；同样的内容占的上下文也少得多。
8. **数据类内容有 JSON。** 时间线、目录、列表这类本来就是数据的内容，给一个 JSON 地址。从 HTML 表格里反推结构容易错位。
9. **`llms.txt`。** 一份 Markdown 索引：站点是什么（一句）、规范地址、订阅源和站点地图的地址、主要页面、内容入口、最近内容。它让 Agent 一次请求就知道站点的结构和去哪取什么。
10. **状态都在地址里。** 筛选、分页、标签页、语言、当前条目都能用地址直接到达（查询参数或路径）。Agent 能直接链接到「某一类的第 2 页」，也能把这个地址交还给用户；只存在于点击之后的状态，它到不了也引不了。
11. **订阅源给全文。** RSS 或 Atom 每条带全文和日期。订阅方取一次订阅源就拿到新条目的全文和日期，不用再逐页取。
12. **`robots.txt` 明确对 AI 爬虫的态度。** 点名写：训练用的爬虫（如 `GPTBot`、`ClaudeBot`、`Google-Extended`）和替用户取页的（如 `ChatGPT-User`、`Claude-User`）可以分开对待。不写就是跟着 `*` 走，那是默认，不是决定。
13. **不用验证码和登录墙挡阅读。** 公开内容不登录就读得到；防滥用靠频率限制。验证码挡住的是替用户办事的 Agent，挡不住有心的抓取。撤不回的动作在站点一侧设意图步（`ux-canon.md` 第 1 节），不靠 Agent 自觉。
14. **机器人和人的统计分开。** 已验证的机器人流量单独记。否则订阅数、点击率这些给人看的指标被机器流量撑大，据此做的产品决定就是错的。

## 参考实现：ranchen.org

2026-11-12 核对过（`/llms.txt`、`/robots.txt` 实际取回）。它做了的：

- `/llms.txt`：Markdown 索引，有标题、一句摘要、规范地址、RSS 和站点地图的地址、主要页面、按来源和类型分的内容入口、最近内容的链接列表。
- `robots.txt`：对所有爬虫放行，只挡后台和私用的几条路径，写明站点地图。
- `/rss.xml`、`/sitemap.xml`；每页有 canonical、描述、Open Graph。
- 文章和回答的地址稳定，带日期、来源和类型：`/content/<日期>-<来源>-<类型>-<slug 或 ID>`；音乐是 `/content/music/<slug>`，不带日期。
- 筛选和分页都在查询参数里（`?type=`、`?source=`、`?topic=`、`?page=`），任何一个列表状态都能直接链接；`llms.txt` 里的内容入口就是这些地址。
- 列表项带类型、时长、日期、摘要；有一个给机器和人联系的邮箱。

它没有提供的（上面第 7、8 条）：Markdown 版正文、JSON 接口，`llms.txt` 里列的机器可读件只有 RSS 和站点地图。JSON-LD（第 6 条）：抽查的页面没发现，取页工具看不到全部的 `<script>`，不能断定没有。照它做能到第 4、9、10 条的水平，其余要自己补。

## 设计阶段要定的

这三样在画板和设计系统里就定下来，写进功能简报；留到实现时再想，字段会缺、地址会改。

1. **每类内容的字段表。** 每个字段：页面上显示在哪、机器从哪读（`<time datetime>`、JSON-LD 的哪个属性、Markdown 头部）。字段至少在一块画板上画出来（`coverage.py --data` 会查）。
2. **地址规划。** 每类页面的地址模式；slug 稳定，公开后只增不删，改了就 301；每个可切换的状态（筛选、标签页、分页、语言）对应的地址写在画板的属性说明里；锚点用稳定的 slug。涉及个人数据的状态不进地址。
3. **每类页面的机器可读件清单。** 一张表：页面类型 × （JSON-LD 类型、Markdown、JSON、进不进订阅源、进不进 `llms.txt`、进不进站点地图）。

画板上同时照做：可点的都是真链接或原生按钮；整行可点的行用一个链接包住；展开的选项始终在 DOM 里；装饰性的 `canvas`、`svg` 加 `aria-hidden`。这些 `verify_canvas.py` 会查（`checks.md`「画出来就要能用」）。

## 怎么查

`python scripts/check_agent_ready.py <站点地址或本地构建目录> --out <报告目录>`

- 不执行脚本取页面（站点用普通 HTTP 请求，本地目录直接读文件），逐项给出 过 / 不过 / 没做 / 没查 和证据。
- 必须项不过时退出码 1。必须项只有五类，划分只看 Agent 取不取得到内容、取到的对不对：正文在原始 HTML 里；`title`、`canonical`、`lang`；可点元素是原生的；没被挡住（`robots.txt` 没有整站 `Disallow`，替用户取页的 `ChatGPT-User`、`Claude-User`、`Perplexity-User` 没被整站禁止：按惯例它们会被挡，有的厂商说明用户发起的取页不一定照 `robots.txt`，所以是「多半取不到」，不是一定）；**做了就要对**（JSON-LD 解析不了、声明的订阅源或 Markdown 取不到、站点地图是空的、`llms.txt` 里的站内链接打不开：坏的 JSON-LD、订阅源、站点地图、`llms.txt` 比没有更糟，Agent 会照着它走）。
- 其余都是可选项，没做或不过只提示：没有 `robots.txt`（按惯例是全部允许）、没有 `sitemap.xml`（页面从首页链接得到就取得到，单页小站可以没有）、标题层级和图片 `alt`（正文取得到，只是切分不准、图里的信息读不到；它们另归 `rubric.md` 的底线）、描述和 Open Graph、上面第 5–12 条。
- 「点名 AI 爬虫」逐个写出允许还是禁止。训练和搜索用的爬虫被整站禁止时报不过（提示）：可以是有意的决定，后果是这些产品里搜不到、引不到这个站，报出来让人确认。
- 站内地址被重定向到别的域名时不跟过去取，记成没查（根域和 `www.` 之间的跳转算同站）；本地目录里 `../` 指不到目录以外，带非法字符的路径按打不开算。
- 连不上的项报「没查」，不算过；没有不过、但有必须项没查成时退出码 2。
- 「列表状态在地址里」是按标记判的（带地址的链接，还是没有地址的标签页和按钮），报告里写出依据；它看不出脚本里同步地址的做法，报不过时人再核对一次。
- 它查不了的：元信息和内容数据对不对得上（抽几篇人工比，或在项目里写比对脚本）、不用验证码挡阅读（无头浏览器走一遍）、统计里机器人和人分没分开（查统计配置）。这三项在评审时人查。

什么时候跑：有了能访问的构建或预览以后每一轮跑；上线前对线上地址再跑一次。
