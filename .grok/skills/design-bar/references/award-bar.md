# 大奖标尺：六个维度的评分口径和「体验与美学」出口门槛

> 什么时候读：选参照作品（第 2 步）、给第一版或大版本定出口标准（开定稿票时）、独立评审打分（第 5 步）、定稿前跑 `scripts/gate.py`。
> 为什么有它：只管「完整、一致、评审通过」的出口标准，定出来的是一份零冲突、合规的版本，不会自动是让人记住的版本。「惊艳」要当成交付物写进门槛，并且有能判定的口径，否则每轮评审各说各的，越改越散。

## 0. 先说清标尺从哪来、谁能参评

- 标尺取苹果设计大奖（Apple Design Awards）的六个类别：Delight and Fun、Inclusivity、Innovation、Interaction、Social Impact、Visuals and Graphics。它们正好覆盖「好不好用、好不好看、对谁好」三件事，比只看视觉的奖项更贴近产品。
- **这个奖只评 App Store 上的 App 和游戏。** 网页、PWA（加到主屏幕的 Web App）不在评选范围内。所以：
  - 要参评，就由原生 App 参评；
  - 网页（包括先于 App 上线的网页版）把六个维度当内部标尺，用同一套口径打分；
  - 网页先上、App 后上时，设计系统第一版就写好每个组件到原生的对应（`app.md`「网页先行、App 后上」），免得做 App 时重做设计语言。
- 参照作品：从近年获奖或入围的 App 里挑 3–5 个和本产品任务相近的（名单在苹果开发者网站的 Apple Design Awards 页面，按年份和类别列出），写进标杆卡，每个写清借什么、不借什么。看不到的就写明是凭一般认知，不编细节。

## 1. 评分口径

- **三档：弱、中、强。** 每个维度列「中」和「强」的条件，都是拿得出证据的事实。「中」的条件全部满足才算中；在中的基础上「强」的条件全部满足才算强；否则是弱。
- 和 `rubric.md` 1–5 分的对应：弱 ≈ 1–2，中 ≈ 3–4，强 ≈ 5。
- **每条条件附证据**：截图编号、视频时间点、实测数字、报告路径。没有证据的条件按不满足算。只有文字描述、没有画出来或做出来的东西，按不满足算。
- **打分人是独立评审**：没看过制作过程，拿到截图、操作视频、标杆卡和本文件，和 2–3 个参照 App 并排截图比。制作者自评不算。
- **底线不过直接判弱**：`rubric.md` 的底线任何一条不过，涉及的维度（通常是包容、交互、视觉）直接判弱，不再看其他条件。

## 2. 六个维度

### 愉悦与乐趣 Delight and Fun

- **中**：有一个签名时刻，能追溯到产品概念（方向五行的「签名」）；签名时刻做成了可交互的动效原型，不是文字或静态图；有减弱动态效果下的静态版本；签名图形在入口或建档里就以种子形态出现，不等到第一次完成任务（`craft.md` §1）；完成主任务的那一刻有反馈（动效、触感、声音至少一种），不只是一行字；乐趣不靠装饰（emoji、彩纸、感叹号）。
- **强**：没看过的人看操作视频时，在签名时刻有反应（评审记下一句看后的感受）；有一样随使用积累、值得截图分享的东西（进度、回顾、收藏），仍然克制，并且离开 App 也成立：图形占卡面一半以上、带时间坐标（第几周、哪天到哪天）、带一个只属于这个人的事实、不带隐私数据、接系统分享，缺一项不算；文案有自己的声音，换个产品名就不成立。

### 包容 Inclusivity

- **中**：下面每项都有实测记录，不只是写进规范：读屏顺序（VoiceOver、TalkBack 或 NVDA 走一遍主路径）、键盘能走完全程、字号放大到 200%（App 用最大动态字体）不截断不重叠、对比度数字（正文 ≥ 4.5:1、大字 ≥ 3:1）、可点区域 ≥ 44、减弱动态效果；浅色和深色都走过主路径；每种上线语言用真实译文走过主路径（伪语言只查版式，不算）。
- **强**：老人、读屏用户、非母语用户之中至少一类真人（或按其做法的走查）走完核心旅程，没有阻塞；文案和图像不预设身材、性别、年龄、能力；弱网或离线时核心任务还能做，或者有体面的降级。

### 创新 Innovation

- **中**：一句话说得清这个产品做了同类没做的什么，说的是对用户的价值，不是技术；这一点在入口第一屏就感受得到，不用翻到第二屏。
- **强**：新做法用得自然，不用读说明就会；评审对照 3 个同类 App 的截图，能指出差别具体在哪一屏、哪一步。

### 交互 Interaction

- **中**：核心旅程 ≤ 2 步、非核心 ≤ 3 步（意图步不计，见 `ux-canon.md` 第 1 节），在可点原型或真机上实测，不是数画板；每次按下 0.1 秒内有反馈，超过 1 秒有「动词 + 对象」的进度；能撤销的动作不确认；每个手势都有看得见的替代操作；出错在原地恢复，不丢输入；只改屏内控件的选择（分段控件、单选、开关）时其余内容原地不动：录屏抽帧，点按后变化的面积超过视口 50% 而去处还是同一屏的，判不过。
- **强**：操作视频里看不到停顿和找按钮；转场保持空间关系（从哪来、回哪去）；平台约定用到位（返回手势、系统分享、触感、系统字号）。

### 社会影响 Social Impact

- **中**：说得清产品给用户的长期好处，而不是停留时长；没有暗模式（诱导订阅、难退订、制造焦虑或羞愧的文案、默认勾选的分享、预选付费：花钱的选择器默认选中付费项，或主按钮在用户选之前就带价格，原则见 `ux-canon.md` 第 1 节）；数据怎么用说得清、能收回；有风险的领域（健康、金钱、未成年人、危机）有护栏，并且由代码兜底，不只靠提示词。
- **强**：说得出改善了谁的什么，有可度量的结果；对困难时刻（危机、不适、失败）有体面的处理路径，画进了画板。

### 视觉与图形 Visuals and Graphics

- **中**：设计语言一致（只用 token、字号来自阶梯），交给评审的证据包里 `verify_canvas.py` 结论 done（已知误报也在同一包里重跑清零，见 `rubric.md` 底线）；上线范围里没有占位图（灰色剪影、「待补充」）；图标同一套，同一类对象的图示（人形、设备、地图）也各只有一套基线（`anti-patterns.md`「多套图示」）；浅色、深色各自设计过（相邻大色面 ≥ 1.3:1）；首屏和首屏以下都过换名测试（`craft.md` §1）。
- **强**：有一套自己的插画或图形语言，用在空状态、落地页、App 图标上；签名图形有一页文法、由同一个生成函数画出，所有状态并排只有一种画法（`craft.md` §1）；旗舰屏（入口、核心任务、回顾）手工精修，不是脚本批量出的模板感；和参照 App 并排不落下风，评审写明比较的结论。

## 3. 「体验与美学」出口门槛

第一版定稿、大版本定稿时，出口标准在「完整、一致、经得起走、独立把关、负责人确认」之外加一列「体验与美学」。下面四条任何一条不过都是阻塞：

1. **动效原型和操作视频**：签名时刻和入口第一屏有可交互的动效原型；核心旅程有一段 2–3 分钟的操作视频，按目标设备尺寸录。负责人看视频确认，不逐张看静态画板。
2. **六维评分不低于中**：独立评审按第 2 节打分，每维附证据，和 2–3 个参照 App 并排截图；任何一维是弱就不过。
3. **无障碍实测报告**：读屏顺序、200% 字号、对比度数字、键盘路径，在真机或真实浏览器上实测；只有自动扫描不算。
4. **步数实测**：核心旅程 ≤ 2 步、非核心 ≤ 3 步（意图步不计），在可点原型或真机上实测，记下每条旅程的点按次数和用时。

四条都写进 `<设计目录>/scorecard.md`（模板在项目设计目录里），定稿前跑：

```bash
python <本技能目录>/scripts/gate.py <设计目录>/scorecard.md --out <设计目录>/reviews/<日期-定稿>
```

它查齐不齐、够不够：六维都有档位且不低于中、每条有证据、参照作品至少两个且有并排截图、交付物都填了（写本地路径的要真的存在）、每条旅程的步数在预算内且是实测。证据属不属实它判不了，由独立评审核。门槛的数值可以按项目改（`--core`、`--other`），改了写进出口标准。

负责人把某项实测移出这一版的范围时（例如第一版网页不做读屏实测），在需求的范围外清单和决定表里写明，记分卡对应维度的证据里写「按负责人某日定的范围，不含某项」，其余各项照第 2 节判档；评审报告把它列为范围决定，不算未达门槛的缺口。只有负责人本人的决定算数，评审和制作方不能自己移；参评苹果设计大奖的版本不适用这一条。

## 4. 定稿纪律

定稿发散，通常不是方向错了，而是「每轮评审都能开新版本」。三条：

- **评审只按出口表判阻塞。** 不在出口表里的意见一律记进「上线后再看」，不触发改需求或改设计。
- **每类评审最多两轮。** 第二轮还不过，回到方案本身重想，不继续打补丁（和 `SKILL.md` 第 5 步「3 轮停止」同一个思路）。
- **设计在前，需求跟着画板收。** 先画核心旅程和签名时刻、出操作视频，画的过程中顺手关掉相关的需求项；不要先把需求全关掉再画，画的时候又会发现需求要改。
