# 检查脚本：查什么、怎么跑

机械检查只报能判对错的问题：给出位置和量出的数，不报审美意见。构图、层级、品位仍然要人看截图（`rubric.md`、`audit.md`）。每个脚本的 `--help` 是完整的说明；这里是总览和容易踩的地方。改检查规则后先跑 `scripts/selftest.py`。

## 先核对「查了什么」，再信「0 个问题」

`verify_canvas.py` 的报告在每块画板标题下写着「查的视口」和尺寸来源。先看这一行：

- 基准视口：同目录 `canvas.json` 的 `w×h` → 画板 `data-props` 的 `$preview` → 都没有时用 390×844，并提示「画板尺寸没找到」。桌面画板按 390 宽查出来的竖排、超出画板全是假象；这时给了 `--size`，第一个 `--size` 就是基准。
- 流式页面（`canvas.json` 里带 `expand`）：视口高度取一屏（宽 ≥ 1024 用 900，≥ 744 用 1180，其余 844），并自动加查 390×844、320×568。根节点不写死宽度的手机画板自动加查 320×568。`--no-auto-sizes` 关掉。
- `--size 名称=宽x高` 再加一个视口（名称可以不带 `.dc.html`，`*` 表示全部）。生成前清单里的视口矩阵，自动没带的用它补。
- 说明文档类画板（组件表、旅程图）不查触控、首屏、空白带、色面、字号种类、左边缘。只有 `canvas.json` 里带 `expand` 的画板才可能算文档：根节点写了 `data-board="doc"`，或者没有 `nav` / `main` / `footer` / `data-first-screen`。固定尺寸的画板写了 `data-board="doc"` 也照查。按文档跳过的画板和原因列在报告开头，交付前看一眼这一行。产品页面被误判时写 `data-board="page"`。
- 画板用 `/_blob/<id>` 引用上传的样式表时加 `--blob <id>=<本地文件>`（可写多次），否则样式读不到，会误报一串「token 没定义」和「触控过小」。

## `verify_canvas.py`（画板）

`python scripts/verify_canvas.py <画板目录> --out <报告目录> --themes light,dark,pseudo`。每块画板 × 每个状态（`<sc-if value="{{ sN }}">`）× `data-props` 的每个枚举选项 × 主题 × 视口。结论 `done`（退出码 0）或 `needs_work`（1）。

| 类 | 查什么 |
|---|---|
| 看不清、点不到 | 对比度（正文 4.5:1、大字 3:1；按下、悬停另算）、主按钮被挡或挤扁、可点元素被盖住、首屏主操作在视口外、深色下露出浅色底 |
| 点按区域 | 独立成行的链接和按钮 < 44×44；任何可点元素短边 < 24（WCAG 2.2 的 2.5.8，报成更重的一类）。页脚、面包屑、整行链接都查。只放过一句话中间的行内链接：在 `p` 里或 `li > span` 里、行内显示、不在 `nav` / `header` / `footer` 里、所在的块里链接以外还有 ≥ 12 个字；`div`、`td` 里的句中链接和 `li > a` 的行标题链接照报。伪元素或子元素撑大的热区（`::before` / `::after`、溢出盒子的子元素）按撑大后的量（2.5.8 量的是目标区域，不是文字盒）：在盒子外按目标尺寸取点，点到的是它或它的子元素才算点得到；撑大的部分要盖得住以盒子中心为中心、目标尺寸的方块（方块每条边取 9 点，两端在边线内 0.5px，全部要点到），只伸出一条比目标尺寸窄的条、偏在一侧、缺一块、圆形或圆角 ≥ 2px 的不算；写了 `pointer-events: none`、被盖住、或取样点在视口外的，照盒子量。量不出来的：两个取样点之间比间距窄的缝（44 下 5.4px、24 下 2.9px）；每个方向撑到超过 43px（23px）就算撑到；盒子和方块的边之间不取样。一屏以下或内层滚动容器里的元素先滚到视口里量，量完把窗口和各层滚动容器放回原处 |
| 版式坏了 | 文字挤成竖排、超出画板、画板比视口宽、冲出容器、短标签多行、按钮折行、弹性布局吞空格、展开层出区块、展开挤动版面 |
| 排版 | 孤字成行、词中断行、中英混排词组被拆开、标点在行首 |
| 全局一致 | **跨画板的内容左边缘**：同一视口宽度下各画板第一个 `h1`（没有就取第一屏第一个标题）相差 > 2px，列出每块的值；有意不对齐的写 `data-edge="free"`。**字号种类**：一块画板 > 8 种，列出每种和次数 |
| 首屏 | **空白带**：入口页第一屏（标了 `data-first-screen`，或流式页面的第一屏）里连续没有文字、控件、图片的空带 > 视口的 30%；加载态的骨架不算空（`aria-busy="true"` 的容器整块、`[data-skeleton]` 和类名带 `skeleton` 的占位块）；只被动效画布盖着的另记提示。首屏主操作在视口外（第一个 `section` 里的按钮和表单；流式页面里从视口下半才开始的 `section` 不算首屏，固定尺寸的画板不加这个条件）。首屏要读的字太多；站标不回首页 |
| 色面 | **相邻两大块色面分不开**：两块各占视口 ≥ 20%、彼此相邻（并排、上下相接、一块套一块）的平涂色面对比 < 1.3:1，浅色、深色各查。边界已经画出来的面算分开，不报：有一层看得见的柔和阴影（不透明度 > 0.1、模糊 > 0；全透明的不算，有模糊、有偏移的 `0 8px 24px rgba(0,0,0,0)` 也不算），或者描边（边框、outline、没有模糊的阴影圈）和两块面里至少一块对比 ≥ 阈值（和面同色的描边不算） |
| 玻璃 | 压在平涂底色上、背景声明不成立 |
| 画出来就要能用 | `<a>` 没有 `href`、`div` 上挂点击、控件没有可读名称、交互绑定写错、可点元素没有悬停或按下样式、浮层没有出路 |
| 源码 | 写死的颜色、没定义的 token、页面报错、占位文字、笼统的进度文字 |
| 提示（不影响结论） | 向第三方取字体（访客的 IP 和浏览器信息会发给第三方；连不上时掉回备用字体，截图和产品不一样）、首屏有一带只有动效画布、模板味信号 |

几条细则：

- 展开挤动版面：某个变体比同尺寸、同语言的第一个变体多展开了一个 `aria-expanded` 控件时，展开层以外的元素移动超过 8px 才报。
- 颜色用 `oklab()`、`color-mix()` 这些写法也能算（画到画布上取像素）；真算不了会报「颜色算不了」，不会悄悄拿外层背景顶替。
- 画板的 `renderVals()` 在浏览器里执行一次（props 取 `data-props` 的默认值），`<sc-for>` 可以嵌套；`componentDidMount` 这类生命周期不执行，所以 WebGL、计时器、透镜画的东西截不到，用下面的 `capture_motion.py`。

阈值写在报告开头。它们都是可配的常量，有同名参数：`--edge-tol 2`、`--empty-band 0.30`、`--face-area 0.20`、`--face-contrast 1.3`、`--tap-min 44`、`--tap-floor 24`、`--max-font-sizes 8`。项目的设计系统定了更严的门槛（例如品牌的两块主色面要 ≥ 1.8:1）时，写进项目配置 `design-bar.json`（`{"thresholds": {"face-contrast": 1.8}}`，键是上面同名参数去掉 `--`），命令不带参数也生效，不改脚本的默认值。`verify_canvas.py` 和 `check_page.py` 从命令行给出的路径往上找，再从当前目录往上找，每层看 `design-bar.json` 和 `design/design-bar.json`，到仓库根为止；命令行参数优先于配置；`--project-config <文件>` 指定，`--no-project-config` 不读。读到配置时报告开头的「阈值」一行写明取自哪个文件。

它量不到的，评审时人看：两块色面之间只隔一条细线算不算分得开；首屏里有一个小元素把空带切成两段时的「空」；元素之间的构图关系；动效画的是什么。

## `capture_motion.py`、`render_dc.py`（截图证据）

`verify_canvas.py` 只填模板，不跑挂载代码，WebGL、计时器、透镜画的东西截不到。

- `capture_motion.py <画板> <输出.png> --state '<json>' [--hover x,y] [--reduced-motion] [--no-webgl] [--expect <选择器>] [--scroll Y] [--focus <选择器>] [--probe <选择器>] --blob <id>=<文件>`：执行画板完整的挂载代码、等透镜解码再截。挂载代码自己改了 state（拿不到 WebGL 就换兜底画面）时，它按新的 state 重新渲染一遍，所以 `--no-webgl` 截到的就是兜底帧；加 `--expect '<兜底元素的选择器>'` 证明兜底真的画出来了（没有时退出码 3）。`--probe` 量玻璃背后会不会变（不变时退出码 2）。
- 签名动效的证据至少四帧：两个交互状态、`--reduced-motion` 的静止帧、`--no-webgl` 的兜底帧。
- `render_dc.py <画板> <输出.png> --state '<json>' --size WxH [--full] [--dark-os]`：单张静态截图核对。

## `check_page.py`（实现出来的页面）

`python scripts/check_page.py <URL 或本地 HTML> --out <报告目录> --dark --widths 320,375,768,1440 [--targets-up-to 1440]`。多宽度截图，检查横向溢出、小字、对比度、点按区域（两级，热区的量法同上，量完同样把窗口和各层滚动容器放回原处；行内例外在上面的条件之外还要求链接的直接父元素是 `P` / `LI` / `SPAN` / `TD` / `DD` / `BLOCKQUOTE`，这是它原来的条件，所以 `p > strong > a` 这类夹一层行内标签的照报）、首屏空白带、相邻色面（`--dark` 时深色也查）、语言声明、`h1` 和标题层级、`alt`、字号和文本颜色种类、reduced-motion、焦点样式、控制台报错；向第三方取字体作提示。空白带和色面与 `verify_canvas.py` 同一套量法和阈值。它不走键盘路径、不触发减弱动态效果，这两项在验收里写明怎么手工验证。

## 改检查的判法时

改的是「什么算问题」（阈值、例外、跳过的条件、取样的方法）时，提交前做两件事：

1. **和改之前的版本做差分。** 用同一批输入（真实画板加构造的样本，构造样本要有专门踩在边界上的）各跑一遍旧版和新版，列一张表：每一条「旧版报、新版不报」的各占一行，写明它对应说明里的哪一条声明（修了哪个误报，或有意放宽了什么）。对不上声明的行就是没声明的放宽，先处理掉再提交。真实样本原来报 0 时看不出这一类，所以必须有构造样本。
2. **量的时候动过页面，量完放回原处。** 会滚动、改窗口尺寸、展开或聚焦元素的检查，量完把窗口、各层滚动容器和状态恢复原状，再进下一项；否则后面的检查量的是被改过的页面。

## 其余

- `check_agent_ready.py <站点地址或构建目录> --out <报告目录>`：见 `agent-ready.md`。
- `lint_tokens.py <源码目录> --tokens <tokens.css>`：写死的颜色和数值、Tailwind 任意值、静态内联样式、`!important`、未定义的 token。
- `coverage.py`、`stale_terms.py`：需求覆盖和过时口径，用法见 SKILL.md「需求变更时」。

## `coverage.py`、`stale_terms.py`（需求和说法）

- `coverage.py --prd <需求文档> --canvas <画板目录> --map <设计目录>/coverage.md --batch '<当前批次>'`：需求里要做的功能哪些还没着落。按功能编号算，看不出「功能里的一部分没画」。内容模型有数据文件时加 `--data <数据.json> --skip-fields <内部字段>`，列出数据里有、哪块画板都没画的字段。
- `stale_terms.py --glossary <设计目录>/glossary.md <路径…>`：按项目词汇表找旧说法，同时读技能自带的通用词汇表 `assets/canon-glossary.md`（跨项目都错的说法，例如主题不跟系统；`--no-canon` 关掉）。决策记录和修订历史里的旧说法不算。

## `check_shell.py`（外壳）

`python scripts/check_shell.py <源码目录…> --config <设计目录>/shell.json --out <报告目录>`。读源码文本，不渲染：有深色主题却没有 `prefers-color-scheme`、根元素写死主题（`theme.fixedAllow` 里的特例路径除外）、约定的存储键和取值没出现、家族首页和同级链接没出现、没有 `aria-current`。不给 `--config` 只查前两项。它判不了「读了存储键是否生效」，上线前照 `family.md` 第 4 节点一遍。

## `gate.py`（定稿门槛）

`python scripts/gate.py <设计目录>/scorecard.md --out <报告目录> [--core 2] [--other 3]`。查记分卡齐不齐、够不够：六维都有档位且不低于中、每维有证据、评审人不是制作者、参照作品至少两个且有并排截图、交付物都填了（本地路径要存在）、步数在预算内且是原型或真机实测。证据真假由独立评审核。口径见 `award-bar.md`。
