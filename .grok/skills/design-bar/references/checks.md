# 检查脚本：查什么、怎么跑

机械检查只报能判对错的问题：给出位置和量出的数，不报审美意见。构图、层级、品位仍然要人看截图（`rubric.md`、`audit.md`）。每个脚本的 `--help` 是完整的说明；这里是总览和容易踩的地方。改检查规则后先跑 `scripts/selftest.py`。

## 先核对「查了什么」，再信「0 个问题」

`verify_canvas.py` 的报告在每块画板标题下写着「查的视口」和尺寸来源。先看这一行：

- 基准视口：同目录 `canvas.json` 的 `w×h` → 画板 `data-props` 的 `$preview` → 都没有时用 390×844，并提示「画板尺寸没找到」。桌面画板按 390 宽查出来的竖排、超出画板全是假象；这时给了 `--size`，第一个 `--size` 就是基准。
- 流式页面（`canvas.json` 里带 `expand`）：视口高度取一屏（宽 ≥ 1024 用 900，≥ 744 用 1180，其余 844），并自动加查 390×844、320×568。根节点不写死宽度的手机画板自动加查 320×568。`--no-auto-sizes` 关掉。
- `--size 名称=宽x高` 再加一个视口（名称可以不带 `.dc.html`，`*` 表示全部）。生成前清单里的视口矩阵，自动没带的用它补。
- 说明文档类画板（组件表、旅程图）不查触控、首屏、空白带、色面、字号种类、左边缘。只有 `canvas.json` 里带 `expand` 的画板才可能算文档：根节点写了 `data-board="doc"`，或者没有 `nav` / `main` / `footer` / `data-first-screen`。固定尺寸的画板写了 `data-board="doc"` 也照查。按文档跳过的画板和原因列在报告开头，交付前看一眼这一行。产品页面被误判时写 `data-board="page"`。
- 画板用 `/_blob/<id>` 引用上传的样式表时加 `--blob <id>=<本地文件>`（可写多次），否则样式读不到，会误报一串「token 没定义」和「触控过小」。

## `verify_canvas.py`（画板）

`python scripts/verify_canvas.py <画板目录> --out <报告目录> --themes light,dark,pseudo`。每块画板 × 每个状态（`<sc-if value="{{ sN }}">`）× `data-props` 的每个枚举选项 × 主题 × 视口。结论 `done`（退出码 0）或 `needs_work`（1）。

| 类 | 查什么 |
|---|---|
| 看不清、点不到 | 对比度（正文 4.5:1、大字 3:1；按下、悬停另算）、主按钮被挡或挤扁、可点元素被盖住、首屏主操作在视口外、深色下露出浅色底 |
| 点按区域 | 独立成行的链接和按钮 < 44×44；任何可点元素短边 < 24（WCAG 2.2 的 2.5.8，报成更重的一类）。页脚、面包屑、整行链接都查。只放过一句话中间的行内链接：在 `p` 里或 `li > span` 里、行内显示、不在 `nav` / `header` / `footer` 里、所在的块里链接以外还有 ≥ 12 个字；`div`、`td` 里的句中链接和 `li > a` 的行标题链接照报。用 `::before` / `::after` 撑大的热区按撑大后的量（2.5.8 量的是目标区域，不是文字盒）；伪元素写了 `pointer-events: none`、被盖住、或取样点在视口外的，照盒子量 |
| 版式坏了 | 文字挤成竖排、超出画板、画板比视口宽、冲出容器、短标签多行、按钮折行、弹性布局吞空格、展开层出区块、展开挤动版面 |
| 排版 | 孤字成行、词中断行、中英混排词组被拆开、标点在行首 |
| 全局一致 | **跨画板的内容左边缘**：同一视口宽度下各画板第一个 `h1`（没有就取第一屏第一个标题）相差 > 2px，列出每块的值；有意不对齐的写 `data-edge="free"`。**字号种类**：一块画板 > 8 种，列出每种和次数 |
| 首屏 | **空白带**：入口页第一屏（标了 `data-first-screen`，或流式页面的第一屏）里连续没有文字、控件、图片的空带 > 视口的 30%；只被动效画布盖着的另记提示。首屏主操作在视口外（第一个 `section` 里的按钮和表单；流式页面里从视口下半才开始的 `section` 不算首屏，固定尺寸的画板不加这个条件）。首屏要读的字太多；站标不回首页 |
| 色面 | **相邻两大块色面分不开**：两块各占视口 ≥ 20%、彼此相邻（并排、上下相接、一块套一块）的平涂色面对比 < 1.3:1，浅色、深色各查。带 `box-shadow` 或可见描边的面算已经分开，不报 |
| 玻璃 | 压在平涂底色上、背景声明不成立 |
| 画出来就要能用 | `<a>` 没有 `href`、`div` 上挂点击、控件没有可读名称、交互绑定写错、可点元素没有悬停或按下样式、浮层没有出路 |
| 源码 | 写死的颜色、没定义的 token、页面报错、占位文字、笼统的进度文字 |
| 提示（不影响结论） | 向第三方取字体（访客的 IP 和浏览器信息会发给第三方；连不上时掉回备用字体，截图和产品不一样）、首屏有一带只有动效画布、模板味信号 |

阈值写在报告开头。它们都是可配的常量，有同名参数：`--edge-tol 2`、`--empty-band 0.30`、`--face-area 0.20`、`--face-contrast 1.3`、`--tap-min 44`、`--tap-floor 24`、`--max-font-sizes 8`。项目的设计系统定了更严的门槛（例如品牌的两块主色面要 ≥ 1.8:1）时，在项目的检查命令里写上参数，不改脚本的默认值。

它量不到的，评审时人看：两块色面之间只隔一条细线算不算分得开；首屏里有一个小元素把空带切成两段时的「空」；元素之间的构图关系；动效画的是什么。

## `capture_motion.py`、`render_dc.py`（截图证据）

`verify_canvas.py` 只填模板，不跑挂载代码，WebGL、计时器、透镜画的东西截不到。

- `capture_motion.py <画板> <输出.png> --state '<json>' [--hover x,y] [--reduced-motion] [--no-webgl] [--expect <选择器>] [--scroll Y] [--focus <选择器>] [--probe <选择器>] --blob <id>=<文件>`：执行画板完整的挂载代码、等透镜解码再截。挂载代码自己改了 state（拿不到 WebGL 就换兜底画面）时，它按新的 state 重新渲染一遍，所以 `--no-webgl` 截到的就是兜底帧；加 `--expect '<兜底元素的选择器>'` 证明兜底真的画出来了（没有时退出码 3）。`--probe` 量玻璃背后会不会变（不变时退出码 2）。
- 签名动效的证据至少四帧：两个交互状态、`--reduced-motion` 的静止帧、`--no-webgl` 的兜底帧。
- `render_dc.py <画板> <输出.png> --state '<json>' --size WxH [--full] [--dark-os]`：单张静态截图核对。

## `check_page.py`（实现出来的页面）

`python scripts/check_page.py <URL 或本地 HTML> --out <报告目录> --dark --widths 320,375,768,1440 [--targets-up-to 1440]`。多宽度截图，检查横向溢出、小字、对比度、点按区域（两级，行内例外和热区的量法同上）、首屏空白带、相邻色面（`--dark` 时深色也查）、语言声明、`h1` 和标题层级、`alt`、字号和文本颜色种类、reduced-motion、焦点样式、控制台报错；向第三方取字体作提示。空白带和色面与 `verify_canvas.py` 同一套量法和阈值。它不走键盘路径、不触发减弱动态效果，这两项在验收里写明怎么手工验证。
