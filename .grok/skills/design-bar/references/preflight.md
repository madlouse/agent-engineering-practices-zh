# 生成前清单

> 什么时候读：第 3.5 步每块画板交出前对一遍（比等评审抓便宜得多），第 5 步实现时再对一遍代码。
> 原则来自 `ux-canon.md`；能机检的都标了脚本，标了脚本的也要先按这里做对，检查只是兜底。新加一条前先看这里有没有同类，有就合并或改写那一条。

## 首屏：不用读就会用

- 不用读就会用：先用图标、位置、进度条、通行约定（站标回首页、齿轮是设置）说清，再补字；说明一处一句；首屏区域标 `data-first-screen`，让检查量出要读的字数。
- 首屏不留超过视口 30% 的空带；动效占的那一带另画静态兜底，并截出来看。首屏有一句定位（是什么、给谁），主操作写清点了得到什么，大数字外行读得懂（判据见 `references/rubric.md`「第一印象」「讲价值」）。
- 首屏要写矮屏退路：先收哪些次要入口、换成哪一档最短的文案；语言会改变按钮占几行，按语言分别查。

## 交互与状态

- 按 `ux-canon.md` 第 1 节列出撤不回的动作，每个最多一个意图步、写清后果；步数表每步标「意图步」或「可删步」，超预算只删可删步。
- 每个超过 1 秒的状态画出来，文字写「动词 + 对象」（「正在订阅」），不写「加载中」；撤不回的动作画意图步，能撤回的画「撤销」（对外发送也可以「延迟 + 撤销」）。
- 状态：用 `data-props` 把页面状态、浮层、订阅这类状态都做成可切换的属性，默认收起展开层，免得遮住别的状态。
- 每个可点元素在真实画板上都有悬停和按下样式（`:hover` / `.is-hover`、`:active` / `.is-press`），不只是控件状态表里的样品有；玻璃控件提亮底色，不叠灰。
- 浮层打开时三件事：焦点进去、Esc 在页面级接住、关上回到触发它的按钮；同类浮层的提示（「按 Esc 收起」）每页一样。
- 有 Agent 替人做事的界面：计划能改、执行能停、做过的事有记录能撤销、失败时说清哪些已生效、AI 生成的内容有标识、个人数据按类别授权（`ux-canon.md` 第 4 节）。

## 外壳、主题和产品家族

- 外壳和共享数据只有一份：多个画板或多个分支并行生成前，先把导航、页脚、文案字典、内容数据抽成一份，分支只引用；跨画板的内容决定（动作、叫法、顺序）由主会话先定。内容左边缘全站一条公式：首屏、下面各区块、各页第一个标题都用同一个边距变量，相差不超过 2px。
- 浅深色默认跟随系统（`prefers-color-scheme`），用户可以手动选自动、浅、深，选择存在一处、刷新和跨页都还在。固定某一种主题只给设计系统里点名的特例屏（例：训练中整屏深色），特例写在 `<设计目录>/shell.json` 的 `theme.fixedAllow`；根元素不写死 `data-theme`。`check_shell.py` 查。
- 和别的产品共用域名、入口或账号时（产品家族），导航按家族约定画：站标回家族首页、同级产品的链接齐全且当前所在的高亮（`aria-current`）、语言和外观的选择读写同一组存储键。约定写在 `<设计目录>/shell.json` 的 `family`，导航在浅深、每种语言下都有画板（`references/family.md`）。
- 导航用不用玻璃看它在哪：吸顶压过正文用玻璃，压在平涂底色上用实色。一个页面同一时刻只有一条吸顶栏（子页面自己的栏滚过首屏后替换全局导航，不叠两条）；吸顶玻璃做一个「正文压在栏下」的状态来看模糊和内光，所有吸顶条在「滚过首屏」时一起看。

## 版式与视口

- 视口矩阵：手机 320×568、390×664、382（折叠屏外屏），平板 744、820，桌面 1280×720、1440×790；首屏的主操作和订阅在每个尺寸下都完整留在首屏，首屏高度按视口算、不写死。
- 自适应的画板根节点用 `width: 100%`、首屏高度用视口算，不写死像素宽度（写死时窄视口查不了，`verify_canvas.py` 报「画板比视口宽」）。
- 独立成行的链接（页脚、面包屑、整行可点的列表行）热区 ≥ 44px，任何可点元素 ≥ 24px（只有正文段落里一句话中间的链接除外）；一块画板的字号不超过 8 种，都来自阶梯；字体自托管或用系统字体栈，不从第三方取。
- 原地展开不挤动版面：展开层挂在触发控件上，用覆盖层（`position: absolute` 叠在上面）或事先预留的空间，不放进文档流；被它盖住的东西用 `visibility: hidden` 保留位置。触发它的按钮和上方的内容一动不动；下方放不下时向上翻转，不压主标题。本来就该把下面推开的折叠列表在触发控件上写 `data-expand="inline"`。
- 收起、隐藏的东西不占位：`opacity: 0` 的同时把高度收到 0（或 `display: none`），否则留下空洞。
- 两栏各自从上往下排时不用 subgrid 按行对齐：一边多一个元素，另一边就整行空着。
- 固定在接缝、角上的装饰（圆、徽章）按自己的尺寸定位，按最长语言、最矮屏幕留位，并和导航一起量空间。后来加了让接缝移动的动效，回头把跟接缝对齐的东西（导航、订阅条、圆）都改成跟着同一个变量走。从桌面搬到手机的元素在手机首屏的构图里重新放，不照搬「右上角」。
- 同一类设备上的同一个操作只有一段标记，不手写两份。
- 出错和空状态在窄屏上不藏说明，让容器跟着内容长。

## 语言与排版

- 语言：每种语言都画、都在最窄的视口下看；固定位置的装饰（圆、徽章）按最长语言的标题宽度留位。
- 中英混排的词组（「AI 发展史」「App 里的」）不拆到两行，不手写 `<br>` 断行。中文用 keep-all 时可断的地方只剩空格，西文词和后面的中文之间写不断行空格（`AI&nbsp;是`），标题和导语加 `text-wrap: balance`。
- 两个选项在最长语言下一行放不下时换排法，不裁字。

## 颜色、材质与焦点

- 相邻的两大块色面对比 ≥ 1.3:1，浅色、深色各看；深色单独设计，不是反色后「没坏」。
- 骑在两种底色上的控件（压在接缝上的圆、跨两块底的按钮）焦点用两色圈：贴着控件一圈浅色、外面一圈焦点色，哪一侧都有一圈 ≥ 3:1。单色焦点圈只按一侧的底色量过，另一侧会掉到 2:1。
- 玻璃：问「它背后是什么」，不问「它重不重要」；背后会变才用，平涂底色上用实色面（压在两块平涂的接缝上也是平涂，只会被劈成两色）；按下、悬停也按 4.5:1 查（深色玻璃按下压暗）。做法见 `references/liquid-glass.md`。
- 玻璃的背景声明要成立：`data-backdrop` 写的是 `motion` 就要真的有动效从它后面经过（跟着动效一起移动的表面背后比例不变，等于平涂）；`scroll` 只给吸顶、固定的表面。同一时刻只有一层玻璃，不叠玻璃。品牌色玻璃的底色超过约 50% 就改实色。模糊按背后分档：小控件 2–4px，吸顶条和通栏 12–24px（`liquid-glass.md` §1）。

## 内容与 Agent 可用

- 内容模型里的字段（数字、结论、出处、日期……）每个都至少在一块画板上画出来；数字卡按「数字 → 结论 → 出处」的顺序排。
- 展开的选项始终在 DOM 里、每个是真链接，不悬停也能到达；装饰性的 canvas 加 `aria-hidden`，它表达的入口另有真链接。
- 给 Agent 读的部分在这一步定：每类内容的字段、地址规划、每类页面的机器可读件（`references/agent-ready.md`「设计阶段」）。

## 证据

- 截动效、透镜、滚动玻璃的证据用 `scripts/capture_motion.py`，不用静态截图工具。
- 跑动效的每块画板都带同一段「动效不可用时的静态画面」。
- 跑验证时把矩阵里自动不带的视口用 `--size` 补上；报 0 时照报告写清查了哪些视口和语言。
