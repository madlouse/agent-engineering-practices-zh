# 多个 Agent 并行画稿：不丢活、不空等

一批画板分给几个 Agent 同时画时用。这些做法来自一次真实事故：五个画稿 Agent 的模型请求挂起，既不报错也不超时；它们又都打算最后一次性写盘，所以三个半小时里没有一块画板落盘，协调者也没发现。

## 分派

- **一个 Agent 管一到三块画板**，不要一个 Agent 包一整条流程。任务小，挂掉的损失就小，重派也快。
- **派活时先建好每个 Agent 的空进度记录** `progress-<组>.md`，还没写出第一行就挂住的也能按时间查出来。
- **先探活再派整批**：对要用的模型先发一个一句话的小任务，一分钟内没回应就换模型，不要整批压上去等。
- 任务说明里写清楚「随写随存」：
  1. 读完必读材料，十五分钟内先把画板骨架写到磁盘（所有状态名、一句话、主卡占位），能生成就行；
  2. 每填完一个状态存一次，不攒到最后；
  3. 每存一个状态，在自己的 `progress-<组>.md` 里追加一行：哪块、哪个状态、还剩什么。这份记录就是心跳；整份任务做完时，最后一行只写「全部完成」；
  4. 开工前先看磁盘上有没有自己的文件和进度记录，有就接着做，不重写。

## 盯进度

- 协调者每十分钟跑一次 `python scripts/watch_workers.py <各组进度记录> --stale 10`。只传进度记录，不传画板文件（画完的画板不再变，会被误报）。超过阈值、最后一行又不是「全部完成」的，或写明的进度记录不存在的，退出码为 1。
- 判定为卡住的 Agent：停掉，按原任务说明重派一次（说明里加一句「接着磁盘上的文件做」）；重派后还卡，换模型。
- 每块画板交回来，协调者当场检查、提交并推到远端，不等整批。容器重启、会话中断时，远端分支上就是最新进度。

## 交接

- 被打断的工作，靠磁盘上的画板文件、进度记录和远端提交接上，不靠 Agent 的上下文。
- 报告里写清楚：用了哪个模型、换过没有、为什么换。
