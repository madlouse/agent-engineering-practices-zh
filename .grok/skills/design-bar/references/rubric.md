# 评分维度与底线

## 评分锚点（1–5）

- 1：有明显问题，影响理解或使用
- 2：能用，但一眼可见是默认值或模板
- 3：合格、整洁，但普通
- 4：专业，能看出每个决定都是有意为之
- 5：令人印象深刻，而且服务于概念，换到别的项目里就不成立

每个分数都要附证据（哪张截图、哪个位置，或者一个测量值）。

## 参照的评审体系

- **Awwwards**：设计 40%、可用性 30%、创意 20%、内容 10%。设计和可用性加起来占七成，炫目但难用的作品拿不到高分。
- **FWA**：更看重创新和交互体验，偏实验性。
- **Apple Design Awards**（App）：Delight and Fun、Inclusivity、Innovation、Interaction、Social Impact、Visuals and Graphics。每维的「中、强」条件和定稿门槛见 `award-bar.md`；这个奖只收 App Store 上的 App，网页把六维当内部标尺。

按项目性质选择参照：商业官网和报告页更接近 Awwwards 的权重，实验性品牌站可以参考 FWA，产品（App 和网页里的工具）用 `award-bar.md` 的六维。

## 通用维度

### 第一印象
- 只看第一屏，能说出“这是什么、对我有什么用、下一步做什么”
- 5 秒测试：让没见过的人只看首屏 5 秒，他说得出「是什么、给谁的」。首屏上有一句定位（对象 + 结果）才过；只有口号或品牌词不算，要读到第二屏才明白也不算
- 同一屏里用户要认的名字只有一个：公司、产品、角色的名字同屏出现两个以上时，其余的带一句关系说明，或者挪走
- 首屏没有超过视口 30% 的空带（`verify_canvas.py`）；动效占的那一带有截出来的画面和静态兜底
- 有一个主导对象，阅读路径稳定
- 眯眼测试：模糊看，层级仍然清楚；把文字遮住，身份、强调、分组和顺序仍然能看出来

### 排版
- 字号阶梯一致，同级元素共用同一角色
- 西文正文行长 60–70 字符；中文正文每行约 25–40 字
- 中文行高 1.6–1.8；标点挤压合理；中西文之间有间距；避免行首标点和孤字成行
- 标题用 `text-wrap: balance`，长段落用 `text-wrap: pretty`
- 中文字体做子集化或使用系统字体栈，避免首屏加载数 MB 的字体

### 版式与留白
- 所有间距来自间距阶梯，每个间距只有一个负责的容器
- 内容左边缘全站一条线：同一宽度下各页第一个标题的左边缘相差不超过 2px（`verify_canvas.py`）
- 组内近、组间远、章节转换更远
- 空白有目的；分栏没填满或孤零零的第三项造成的大块空白，算作版式问题。不只入口第一屏：核心任务的每个状态里，内容下方连续空带超过视口 30% 时，要么上移主操作，要么放签名图形，要么在设计系统里写明理由，三者都没有算不过
- 图形元素和它对应的刻度标签对齐：中心相差 ≤ 2px，标签到图形的间距 ≤ 16px；SVG 里的元素也算

### 层级
- 每屏一个主 CTA
- 同一语义的控件全产品只有一种样子，规则写进设计系统（`anti-patterns.md`「控件混搭」）
- 层级首先靠字号和字重，其次才是颜色和容器
- 主操作的文字是点下去得到的结果；点下去先要登录的，按钮旁写清登录后得到什么，或者先让人用、再登录

### 色彩
- 文本对比度 ≥ 4.5:1，大字 ≥ 3:1
- 颜色有语义角色，不靠颜色单独传达信息
- 深色模式单独设计，不是「没坏」就算：品牌色面在深色下仍然认得出、分得开（相邻的两大块色面对比 ≥ 1.3:1，`verify_canvas.py`）；强调面不消失在页面底色里；逐元素量过对比度

### 动效
- 每个动效都有目的：引导、反馈、保持连续或叙事
- 界面级动效 150–400ms
- 支持 `prefers-reduced-motion`；不劫持原生滚动；阅读不需要等动画

### 微交互
- 所有可交互元素都有 hover、focus-visible、active、disabled 状态
- 键盘可完成所有操作
- 操作后 100ms 内有可见反馈

### 响应式
- 320–1920 宽度内无横向滚动
- 移动端是重新编排，不是桌面的缩小版
- 独立成行的可点元素 ≥ 44×44px（页脚、面包屑、整行链接都算，所有宽度）；任何可点元素短边 ≥ 24px

### 原创性
- 有一个能追溯到概念的签名时刻
- 没有出现未经说明的具名反面模式
- 模板测试：把产品名换成别的产品，这屏不成立（`craft.md` §1）。首屏以下的每一屏也做一遍：首屏有概念、往下是通用的区块堆叠，按不过算
- 一屏只有一两处高光，外壳安静

### 讲价值
- 对比、方案、引导先用一个真实场景讲清「对我有什么不同」，功能清单在后
- 文案说的是结果（「训练改到 20:30，日历已改」），不是能力（「智能改期」）
- 数字卡的大字外行读得懂：读得出「什么变了、变了多少」（「等待时间少了 40%」）；统计量、单位不明的差值（「d = 0.4」「p < 0.05」）放到方法一行

### Agent 可用
- 不执行脚本也读得到正文；标题层级、原生控件、可读名称、`alt` 齐全；每页有 title、描述、canonical、语言
- 每条内容的字段（作者、日期、出处、授权）页面上看得到，机器也读得到；状态都在地址里
- 机器可读件由同一份内容数据生成；做了的都是对的（`scripts/check_agent_ready.py`；做法见 `agent-ready.md`）

### 状态完整
- 需求里要做的功能都有画板或写明无界面（`coverage.py`）
- 每个关键界面有：默认、第一次、空、出错、完成的那一刻；浅色和深色都看过（`verify_canvas.py`）

### 内容
- 真实、具体，有品牌声音，没有占位文案和空话

### 性能
- LCP < 2.5s、CLS < 0.1、INP < 200ms（能实测时以实测为准）
- 图片格式和尺寸合理，首屏关键资源优先加载

## 底线（不可让步）

- 文本对比度达标
- 可以用键盘操作，有可见的焦点样式
- 支持 reduced-motion
- 无横向溢出
- 图片有替代文本，标题层级正确，有页面语言声明
- 不使用虚构的数据、评价或客户 Logo
- 主操作在第一屏完整可见，不被底部输入区或标签栏挡住；文字加长 35%（换语言）以后仍然如此
- 画出来就能用：控件是真的 button / a href / label，只有图标的按钮有可读名称
- 画板验证结论为 done，而且报告里「查的视口」和画板的设计尺寸对得上；交给评审的证据包里就是 done，已知误报在同一包里修掉检查或按检查的约定标注后重跑清零，另附说明不算
- 对外页面：`check_agent_ready.py` 的必须项都过（必须项只管 Agent 取不取得到内容、取到的对不对；站点地图、标题层级、`alt` 这些是它的提示，标题层级和 `alt` 归上面那条底线）
