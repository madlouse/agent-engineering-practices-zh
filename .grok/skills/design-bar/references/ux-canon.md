# 体验原则总纲：给人用的界面（GUI）、人和 Agent 一起做事（AUI）、Agent 来用的网站（AX）

> 什么时候读：开工前定方向（第 1 步）、生成前清单（第 3.6 步）、评审和打磨（第 5 步），以及任何人提出新的体验原则时。
> 这是跨产品的通用版本，第 3 版（2026-11-08：按冷评审改过，再按「参考不照抄、回到产品目标、Agent 原生」反思过一次）。项目把它落成自己的规则表：原则不重抄，只写项目的数值、对标和检查。项目在自己的仓库里留一份复核记录，写明哪条采纳、哪条没采纳、为什么。
> 来源：苹果 HIG（2026-06-08 重新发布的设计原则，以及 Generative AI、Machine learning 两页）、迪士尼 Imagineering 和乐园运营、Vercel 的 Web Interface Guidelines 和 design.md、Shopify Polaris、Anthropic 和 OpenAI 公开的 Agent 设计、微软 Human-AI Interaction 18 条、Google PAIR、NN/g。

## 0. 一句话

**让人以最少的负担，在自己掌控、看得懂、信得过的前提下达成目标；替人办事的 Agent 也是用户。**

「最少的负担」不是「最少的点按」。负担有五种：要读的字、要做的决定、要记住的东西、等待的焦虑、出错的代价。规则不只数步数，也数关键时刻里的决定。

## 1. 两个术语（各处只引用这里的定义）

- **撤不回的动作**：撤销窗口内，没法把**外部世界**恢复原状的动作。判法只有一条：效果有没有外泄，也就是有没有发出去、有没有被别人看到、有没有被用户照着做了。常见的有：付款或扣费；对外发送，指邮件、消息、公开发布；删除别人也看得到的内容；删除账号或数据；把个人数据分享给第三方；改动线上数据或别人的东西。界面上有「撤销」按钮，不等于撤得回：提醒已经推送出去、计划已经被照着练了，都属于撤不回。
- **意图步**：用户为一个撤不回的动作确认意图的那一步。每个撤不回的动作**最多一个**意图步，它要写清后果。一个场景里有两个以上意图步时，要在设计决定里写明理由。步数表里每一步标「意图步」或「可删步」；意图步不计入步数预算，也不许为了省步数去掉。其余都是可删步，超预算就删可删步、改设计。

对外发送也可以不确认，改成「延迟加撤销」：先不发，给一个撤销窗口，窗口过了才真正发出去（Gmail 的撤销发送）。乐观更新，也就是不等服务器返回就先改界面，只用在可撤销的动作上。

## 2. 九条原则

「怎么判」一列的标记：
- **〔检〕**：可以写成自动检查。项目要写明用哪个检查；还没有的，写明待做的票。
- **〔人〕**：只能人判。

| # | 原则 | 为什么 | 怎么判 | 主要出处 |
|---|---|---|---|---|
| 1 | **目的先行，内容优先**：第一屏就是论点或工具，不是刊头加铺垫；每屏先回答「这是给谁的、能做什么、下一步是什么」；每节回答一个新问题 | 人来是为了做事。苹果说 Simplicity 不是极简，而是每个元素都配得上它的位置 | 首屏有受众词、一个主操作〔人〕；遮住装饰，任务照样能完成〔人〕；每个论断只有一个证据位置，不重复摘要〔人〕 | HIG Purpose、Simplicity；迪士尼 story first、wienie；Vercel design.md |
| 2 | **沿用熟悉的约定，看得懂就会用** | 学新约定是负担，熟悉让人一来就知道怎么用 | 站标回首页〔检〕；放大镜是搜索、带下划线的是链接、当前位置高亮〔人〕；只用图标的按钮限于通行图标〔人〕；首屏要读的说明有字数上限〔检〕 | HIG Familiarity；Krug《Don't Make Me Think》；NN/g 图标研究 |
| 3 | **只删不承载意图的步骤；把准备挪到关键时刻之前** | Agent 原生的产品里，可撤销的例行事务目标就是**零步**：Agent 在人想到之前做好，人只看结果或到场。「零步是神话」只在撤不回的动作上成立：自动化拿掉了一个隐含的意图信号时，要补一个明确的：Face ID 把「验证身份」和「确认意图」拆开后，苹果给 Apple Pay 加了一步双击确认付款。负担落在什么时刻比步数更要紧：迪士尼让游客在入园前订好快速通道，因为没人想在游玩当天做规划 | 步数表按第 1 节标意图步和可删步〔人〕；关键时刻（训练中、付款时、发布前）里要做的决定不超过项目定的上限〔人〕；Agent 的活尽量在人到场之前做完，把等待从关键时刻挪走〔人〕 | HIG Agency；Apple Pay；迪士尼 Lightning Lane（证据不完全一致）；Polaris「用摩擦突出重要决定」 |
| 4 | **即时回应，设计等待** | 「快」分两层：回应是按下就有反馈，完成是拿到结果。生成式任务做不到 1 秒完成，但能 0.1 秒回应、说清在做什么 | 默认值：按下 0.1 秒内有反馈；不涉及生成的操作完成 P95 ≤ 1 秒；转圈延迟约 150–300ms 才出现，出现后至少显示约 300–500ms（防闪）；超过 1 秒写「动词 + 对象」的进度，不写「加载中」〔检〕；超过 10 秒允许离开，完成后通知（通知受打扰预算约束） | NN/g 响应时间三界限；WWDC18 Designing Fluid Interfaces；Vercel Web Interface Guidelines；HIG Generative AI；Maister 等待心理学 |
| 5 | **默认授权，看得见、撤得回；只在少数场景确认** | 默认授权：人用一次同意把例行的事交给产品和 Agent（Agent 原生产品的前提），之后不再逐项弹窗；换来的是每件事都看得见、撤得回、能随时收回授权。要确认的只有项目列出的少数场景，至少包括撤不回的动作。每步都确认，确认就成了习惯性点击：Claude Code 的手动确认 93% 都被同意了（Anthropic 自己的数据，用户是开发者）。一步不确认又会闯祸 | 项目有一张「要确认的场景」清单，由产品负责人确认〔人〕；每个动作按第 1 节标「可撤销」或「撤不回」〔检〕；可撤销的直接做、做完给撤销，窗口时长由项目定；清单里的场景有一个意图步，写清后果；授权能在一处随时收回〔检〕；导引流程能跳过、能退出〔人〕 | HIG Agency、Generative AI；[Anthropic：Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)；[Anthropic：Measuring agent autonomy](https://www.anthropic.com/research/measuring-agent-autonomy)；Vercel；Polaris |
| 6 | **可信：说清是什么、从哪来、多有把握** | 生成内容看起来权威，人不核对；暗中个性化，人不知道结果为什么变了 | AI 生成或合成的内容有可见标识〔检〕；说法可以简化，论断不能简化，改变含义的限定语一个不丢〔人〕；事实附可点的出处〔人〕；后果严重的数字和判断（健康、金钱、安全）由确定的来源给出，或者标明来源和把握〔人〕；把握用用户能照着做的形式表达，概率本身就是用户要用的信息时才显示百分比〔人〕；把握不够时不主动推，门槛由项目定〔人〕；系统记住了什么，人能看到、能删除〔检〕 | HIG Responsibility、Generative AI、Machine learning；微软 G1、G2、G11、G12–G18；PAIR；Anthropic 宪法 |
| 7 | **连续：不重来、不丢状态** | 再登录、刷新后从头来、换设备找不到刚才的位置，都是在重复劳动 | 同一产品内不重复登录；跨产品跳转时把上下文带过去〔人〕；语言、筛选、标签页、展开、输入了一半的内容，在刷新、后退、分享后都还在，主要状态写进地址〔检〕；**例外**：涉及健康和个人数据的状态不进地址，也不进统计 | HIG Flexibility「保留上下文」；迪士尼 MagicBand 串起旅程；[Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines)「URL as state」 |
| 8 | **替人办事的 Agent 也要能用** | 主流的浏览器 Agent 读无障碍树、DOM 或截图中的一种或几种（Claude 的浏览器工具先读结构，OpenAI 的 Operator 以截图为主）。无障碍是 Agent 可用的前提，但不是全部：验证码、登录墙、不在地址里的状态，跟无障碍无关，照样挡住 Agent | 可点元素是原生控件、有可读名称〔检〕；展开的选项不靠悬停才出现〔检〕；没有透明层盖住可点元素〔检〕；正文不执行脚本也读得到〔检〕；结构化数据、站点地图、RSS 由内容数据生成〔检〕；地址只增不删，改了一律 301〔检〕；读内容和低风险的表单不用验证码，防滥用靠频率限制和二次确认〔人〕 | [web.dev：AI Agent 的网站体验](https://web.dev/articles/ai-agent-site-ux)；Google AI 搜索指南；Claude 浏览器工具文档；OpenAI ChatGPT agent；Netlify AX；W3C Cool URIs |
| 9 | **装饰要证明自己有用** | 惊喜来自好用，不来自装饰；装饰的成本（性能、可读性、维护）常被低估 | 动效先过必要性检查：说清因果，或者一处刻意的签名（营销首页上的一处品牌签名算有用）〔人〕；动画进行中，输入立刻生效（可打断）〔人〕；材质（玻璃、透镜）先回答「透过它看到的东西对人有没有用」，并且有项目定的性能预算〔人〕；品牌表达不挡任务〔人〕 | HIG Delight「Don't mistake delight for decoration」；Polaris；Vercel 动效规则；OpenAI 应用规范 |

## 3. 冲突时的先后（自定）

原则会打架，所以要写一个先后。下面的顺序是**自定**的，参照了两个排列：迪士尼 Four Keys 的列出次序（安全在礼貌之前，原文没有明说这是优先级），以及苹果 HIG 2026 版的条目次序（Responsibility 在 Delight 之前）。理由是：伤害和欺骗没法用后面的好处补回来，而好看可以让位，事后再补。

1. **安全、诚实和保真**：
   - 不伤害人：健康、金钱、隐私、撤不回的后果（「默认授权」也让位于这一级：确认清单里的场景照样要确认）。**防滥用不属于这一级**，优先用频率限制和二次确认解决。
   - 不骗人。
   - 给定的事实、数字、单位、限定语，一个不改。
   - 对应原则 6，以及原则 5 里「撤不回的要确认」。
2. **无障碍底线**：对比度、键盘、读屏、可点区域。对应原则 8 的前提部分。
3. **人掌控**：撤销、退出、停止、状态不丢。对应原则 5 其余部分、原则 7。
4. **完成任务**：对应原则 1、3、4。
5. **看得懂**：对应原则 2，以及原则 8 里不属于无障碍底线的部分。
6. **设计语言一致**：只用 token，同类元素用同样的做法。
7. **好看和惊喜**：对应原则 9。

例子：
- 省一步和确认付款冲突：保留确认（1 先于 4）。
- 玻璃好看和文字对比度冲突：换实色（2 先于 7）。
- 首屏少读字和说清 AI 生成冲突：保留标识（1 先于 5）。
- 完成后通知和打扰预算冲突：守住打扰预算，攒到下一个合适的时刻再说（3 先于 4）。

## 4. 人和 Agent 一起做事（AUI）的规则

产品里有 Agent 替人做事时，按产品选用这几条（不是每条都要；一条规则对这个产品的目标没有帮助，就不加）。用到的每条都写明非视觉的等价物，例如口令、触感、播报，因为人可能正腾不出手，只能扫一眼。

**最要紧的一对**：默认授权（原则 5）和活动记录是一体的。Agent 不问就做，前提是做了什么人一眼能看到、一步能撤回；只有授权、没有记录，是失控。

| 规则 | 怎么查 |
|---|---|
| 先说清能做什么、常在哪出错；空状态给 2–4 个能直接点的用例 | 〔人〕设计评审 |
| 人说结果，Agent 给可编辑的计划或预览；常用约束做成控件，不靠打字 | 〔人〕走一遍 |
| 每个主动动作在配置里声明自主等级，以及按第 1 节是否撤不回；撤不回的必须有意图步 | 〔检〕对动作配置做 lint |
| Agent 执行时，停止一直可用（按钮或口令），1 秒内生效，已完成的部分保留 | 〔检〕端到端 |
| 有一条活动记录：Agent 替人做了什么、为什么、是哪个 Agent 做的；可撤销的每条能撤销 | 〔检〕端到端 |
| 跨会话的任务把步骤、当前步、下一步存在服务端，中断后从断点继续 | 〔检〕端到端 |
| **失败时说清楚**：哪些已经生效、哪些没有、怎么补救；给一条不经过 AI 的后备路径 | 〔检〕端到端（断网、服务出错各走一次） |
| **说完成时附证据**：结果、改了什么、在哪看 | 〔人〕抽查 |
| 生成结果旁有编辑、撤销、重试中的至少两项；人的修正立刻生效，并被记住 | 〔检〕组件测试 |
| 主动提醒受打扰预算约束，不在人正在做的事中途打断 | 〔检〕规则引擎单测 |
| **撤销是信号**：人撤销了 Agent 的某类动作，这一类在一段时间内（由项目定）改为先问；连续被接受也只记成「观察」，人明确说好才变成默认 | 〔检〕规则引擎单测 |
| **授权一次、随时收回**：开始用的时候一次同意（写清会用哪些数据、做哪些事）；之后不逐项弹窗；有一处能按类别收回授权，收回后下一次行为不再用 | 〔检〕端到端 |
| 生成式界面只用组件目录里的类型拼，props 过 schema 校验，不渲染模型给的任意 HTML | 〔检〕单测 |
| 少问：Agent 能用默认值做决定的就做，做完告诉人、给撤销；只在第一次需要偏好时问一次并记住；涉及安全和确认清单里的场景时必须问；都给可点的选项 | 〔人〕抽查 |
| 敏感输入（密码、付款）由人自己输入，Agent 不看、不存 | 〔人〕走一遍 |
| 多个 Agent 一起做事时，人面对的是一个负责的声音；Agent 替人对外发消息时标明是代发 | 〔人〕走一遍 |

## 5. 给 Agent 用的设计说明怎么写（design.md 式）

设计规范要让 Agent 读了就做对，不只是让人看懂。做法来自 Vercel 的 [design.md](https://vercel.com/design.md) 和[配套博客](https://vercel.com/blog/how-our-agents-build-on-brand-pages-with-design-md)，本技能和项目的版式技能都按它写：

1. **写成技能**：先说清「什么时候用」和「你是谁」，再写先后顺序。
2. **判断写成文字，机械的交给接口和检查**：
   - Agent 只用公开的 token 和类名，不读样式表的实现，不自己发明类名或 token（`lint_tokens.py` 查）。
   - 找不到合适的，就用语义 HTML 加页面自己的钩子。
3. **冲突时的先后写在最前面**，见本文第 3 节。
4. **只在关键处提问**：未知会改变事实含义、法律或安全说法、隐私、公式、人群或行动号召时，问一组问题；否则标出缺口，继续做。
5. **点名反模式**：模型认得出有名字的模式，笼统的「别有模板味」不管用。清单见 `anti-patterns.md`。
6. **四遍**：
   1. 框定读者要做的事。
   2. 选构图：先说出这一品类显而易见的默认版式，材料配不上就不用；私下比较两种结构不同的方案。
   3. 按视觉系统做。
   4. 自己渲染、检查、改，直到没有已知问题。交付成品，不交分数和过程日记。
7. **同一条意见出现第二次，就同时写进规范和一条确定性检查**。只在一个模型上出现的问题先不写，等它在多个模型上重复再写。

## 6. 已经被推翻或要警惕的说法

| 说法 | 结论 | 理由 |
|---|---|---|
| 「零步」是神话 | 只对撤不回的动作成立 | Agent 原生产品里，可撤销的例行事务零步就是目标；撤不回的才补意图步。见原则 3 |
| 「一秒」对所有操作 | 改成两层 | 见原则 4 |
| 「三次点击规则」 | 推翻 | NN/g 的数据不支持；点按次数不等于负担 |
| 每步都让人确认才安全 | 推翻 | 确认疲劳；按后果分级 |
| 界面上能撤销就算可逆 | 推翻 | 按外部后果判，见第 1 节 |
| 对人无障碍，对 Agent 就可用 | 说过头 | 无障碍是前提，不是全部，见原则 8 |
| 沉浸感（迪士尼乐园式） | 工具类产品里要警惕 | 乐园靠藏起外部世界、操纵尺度感，搬到工具上就成了藏系统状态、暗黑模式 |
| 玻璃越透越像苹果 | 要警惕 | 苹果的 Clear 玻璃要同时满足三个条件才用，iOS 26.1 又补了 Tinted 开关；阅读类产品默认用厚一档的玻璃，「看得到背后」只是允许用玻璃的门槛，不是目标 |
| llms.txt、WebMCP 能带来流量 | 不当成规则 | llms.txt 是提案，Google 搜索不读它；WebMCP 是社区组草案，只在源试用里有。做了的话由内容数据生成，但不为它们改架构 |
| 熟练用户的工具（Polaris 后台）只用图标 | 只适合每天用的工具 | 第一次来的访客要通行图标加文字 |
| 不要玻璃、默认静止、不要庆祝（Vercel design.md） | 只适合它的场景 | 那是给做决定的高管看的报告页的口味；可以借的是背后的检验「装饰要证明自己有用」，不是禁令 |

## 7. 怎么用

1. **开工前**：
   - 读第 0–3 节。
   - 在功能简报里写清：哪些动作撤不回、各自的意图步是哪一步、关键时刻是哪一刻、有没有 Agent 在替人做事。
2. **生成前清单**：
   - 标〔检〕而且项目已经有检查的，必须通过。
   - 标〔检〕但还没写成检查的，在评审报告里逐条列出，并开票。
   - 标〔人〕的，交给评审。
3. **评审**：按项目的规则表打分，有冲突时按第 3 节裁决。
4. **参考不照抄**：对标产品的规则先问三件事再用：它要解决的问题我们有没有；它的场景（谁在用、多常用、人做还是 Agent 做）和我们一样不一样；加进来以后，离产品的最终目标更近还是更远。只借机制和原理，不借口味；能替换或合并旧规则的才加，规则总数不跟着研究一起涨。
5. **复核**：
   - 有人提出新的体验原则，或者对标产品发布了新版规范时，先在这里判一次：它和哪条原则重合、要合并还是升级、证据够不够、在什么场景下不成立。
   - 结论写回本文件第 6 节，再改项目的规则表。
   - 每条原则在新证据出现时都可以被推翻，第 3 节的先后也一样。
