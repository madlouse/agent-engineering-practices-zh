# Velicoach 版式规范

本技能管 velicoach.com 主站和三站（站稳、看清、动手）的页面怎么排：骨架、版式、阅读排版、组件位置和交付检查。文字本身怎么写见 `velicoach-content` 技能；Veli App 和 Veli 网页版以 Veli 设计系统为准，不适用本技能。

## 1. 唯一来源

- **Velicoach 设计系统**（Claude Design 的 Design System 类型，链接见 `docs/uiue/design-system.md`）是颜色、字体、间距、圆角、玻璃、动效、断点的唯一来源。开工前先读它的 README，再读 `tokens.json`；仓库里的副本在 `docs/uiue/system/`（现在是 v1.1，还有画板共用的样式表 `canvas.css`）。**数值和组件的细则只写在设计系统里**：字号阶梯、栅格公式、各组件的结构和状态、每类页面在手机和平板上怎么排，本技能不再抄一遍，只写「排一个页面时按什么顺序想」和指到设计系统的哪一节；两边不一致时以设计系统为准，并回来改本技能。
- 需求以主站 PRD 为准（`docs/prd/velicoach.md`，在线文档是唯一来源）；设计上的取舍记在 `docs/uiue/decisions.md`。
- 样式只引用 token（`--vc-*`、`--space-*`、`--radius-*`、`--duration-*` 等），不写死颜色、字号、间距、圆角和时长。媒体查询里不能用 CSS 变量，断点写死同值并注明来自哪个 token。
- 需要新 token 或新规则时，先改设计系统，再同步到代码；不在页面里临时发明。
- 「好看」「好用」「舒适」「有品味」这些词的意思以 `docs/standards/quality-terms.md` 为准（规则 U、V、A）；设计评审按 `docs/uiue/bar-sheet.md` 的 P1–P5 打分。和本技能冲突时以那里为准，再回来改本技能。
- 流程沿用 `design-bar` 技能：开工前确认关键信息与标杆，交付前跑检查，评审意见写回设计系统。
- 三个产品共守的设计底线（Apple 语言、一站一键一秒、token、双语、可达性、儿童档）在同级目录的 velicoach-mono/standards/design.md；改共享外壳、登录或设计 token 前先读它和 velicoach-mono/map/repos.md 的共享契约，改完通知 Veli 和种星词的频道。

## 2. 开工前回答四个问题

1. **这页属于哪一站？** 决定底色、正文色、强调色和字体：站稳是纸色、无衬线、苔绿强调；看清首屏是墨色、衬线标题、朱砂强调；动手首屏是苔绿、无衬线、琥珀强调。强调色只在自己的底上出现。
2. **每一屏讲哪一件事？** 列出每屏的一句话；一屏讲不清一件事，就拆成两屏。
3. **这页的主动效是什么？** 首页是「叶与网」，分站只用几乎静止的纸墨质感，内容页没有主动效。
4. **读者在什么设备上读？** 文章页按手机优先排；首页按三档分别出稿。

## 3. 一站、一键、一秒

**一站**：不让用户离开、不让用户再登录一次（主站和 Veli 同一个域名；主站 v1 不读登录状态，登录在 Veli 里完成；订阅、切换语言都在当前页完成；搜索在 v1 不做）。**一键**：见下面的步数。**一秒**分两层：按下 0.1 秒内有回应；不涉及生成的操作完成 P95 ≤ 1 秒；生成类（讲解、威利排计划）不求 1 秒完成，写清在做什么（「正在订阅」「在挑今天的动作」），不写「加载中」。**一键**里的确认不是浪费：撤不回的动作（术语表）各有一个意图步，不计入预算。总纲和冲突时的先后见 `design-bar/references/ux-canon.md`。**不用读就会用**（C10）：看图标和位置就懂：站标回首页、带下划线的是链接、当前位置高亮；进度、数量用图形（进度条、数字）不用一句话；首屏说明不超过中文 80 字、英文 50 词，一处一句；画首屏时在区域上标 `data-first-screen`，`verify_canvas.py` 会量。

**核心场景两步内完成，不常用的场景不超过三步。** 一步是一次有意的点按或提交；滚动和打字不算；系统弹出的账号选择算一步。逐个场景的步数表在 PRD 第 4 节「步数预算」，新页面、新功能先在那张表里加行，再出稿。

- **首屏就是操作台**：核心场景的入口都在第一屏，用户不需要先点一个按钮、再加载一个页面才找到要做的事。
- **按钮直达结果**：文字写点了之后得到什么（「开始训练」「读最新文章」），点了就到，不经过介绍页；不写「了解更多」。
- **原地展开**：一个入口后面有几个去处时（「开始训练」：用 Google、用 Apple，桌面上另有在手机上打开的码），不跳到页面下方或另一页去选，在入口旁边直接给出选项，每个选项直达结果。有悬停的设备（宽度 ≥ 744px）上鼠标停留 80ms 就展开（自定，关口四用真实鼠标轨迹测误触后再定），可以移进卡片，离开 300ms 收起，Esc 收起，悬停不算一步；点按或 Enter 直接进入 `/app`，不展开；键盘聚焦同样展开；触屏（不论宽度，含 ≥ 1180px 的 iPad 横屏）和手机版式（< 744px，不论有无悬停）上选项直接摆在按钮的位置，带动词（「用 Google 开始训练」），两个去处分主次：第一个实心、第二个描边，尺寸相同；苹果设备上 Apple 在前，其余设备 Google 在前（设计系统「页面外壳」「原地展开」；理由见 `docs/uiue/decisions.md` 2026-11-12）。悬停或聚焦时提前连接下一步的地址。悬停只是更快，不是唯一的路（WCAG 2.2 的 1.4.13）；选项始终在 DOM 里、每个是真链接，Agent 和读屏不悬停也能找到（`quality-terms` X3）。只有一个去处的入口不做展开。**展开不挤动版面，也不压别的入口和说明**：展开层是叠在上面的覆盖层，触发它的按钮和它上方的内容一动不动；首页的「开始训练」在按钮右边同一行展开，不压主标题、说明、快捷入口和订阅条；同一时刻只展开一个浮层；本来就该把下面推开的折叠列表（时间线的里程碑、文章目录、文字稿）用 `details` / `summary`，在触发控件上写 `data-expand="inline"`。`verify_canvas.py` 比较展开态和默认态，展开层以外的元素移动超过 8px 就报「展开挤动了版面」。细则见设计系统「原地展开」。
- **少一步的其他做法**：直达、卡片里直接操作、原地切换、卡片展开成页面（视图过渡加预先加载）、认出回来的人（一键登录、通行密钥；v2，主站 v1 不读登录状态）、记住选择、撤销代替确认。每种什么时候用、不采用哪些，见设计系统「少一步的做法」。v1 不做的：本站的操作条、搜索即命令、内容线悬停展开最新三篇（PRD v2.0；搜索和命令在 v2 评估）；原地展开有两种：展开成表单的，v1 只用在「开始训练」和「订阅」的邮箱框；列表的折叠行（里程碑、学习路径的步骤）默认收起、原地展开。
- **登录在 Veli 里完成**（主站 v1 不读登录状态，需求第 80 条）：「开始训练」的原地展开里，Google、Apple、扫码都去 Veli，在 Veli 登录过的人由 Veli 直接带到今天的训练。首页 v1 不放「今天的训练」入口（读登录状态以后在 v2 做）。
- **分清登录前后（v2）**：未登录给「开始」，已登录在同样的位置给「继续」（今天该练的、上次没读完的）；读到登录状态之前按未登录显示，位置预先留好，页面不跳动。
- **在对的时刻提示**：文章末尾的「接着读」里给去另一站的入口，其中有「今天的训练」；训练完成后给「最新文章」是 Veli 一侧的事。两站互相带人。
- **不用操纵手段**：不倒计时，不用羞辱式的拒绝按钮，同意项不预先勾选；关掉任何东西只要一步。
- 交付时逐条走 PRD 的步数表，数出每个场景的实际步数，每步标「意图步」或「可删步」（术语表）：超出预算先删可删步、改设计；剩下的意图步按术语表的清单标明，不算超预算。

## 4. 页面骨架

| 页面 | 从上到下 |
| --- | --- |
| 首页 | 首屏（定位句、站稳与看清左右拼接、「动手」圆在接缝上、叶与网占上半、底部订阅条或 RSS 行）→ 论点（一句大字加三行，每行讲一个「为什么是这个顺序」的因果，入口是行内文字链接）→ 证据（三项研究按证据可信度分级：可信度高的一张通栏大卡，低和很低的各一行）→ 最新（最新文章的强调卡、最新一条开发日志）→ 页底订阅 → 页脚 |
| 看清首页 `/mind` | 墨色色带（站名、一句描述、两条内容线的分段控件、到学习路径的入口、这一页的数据图）→ AI 发展史：按五个时代分段的时间线，里程碑默认收起、原地展开；人机协作（`/mind/collaboration`）：三层，范式行加卡片 → 页底订阅 → 页脚。没有类型筛选，没有按内容线分的 RSS |
| 学习路径 `/mind/learn` | 墨色色带（面包屑回 `/mind`、标题、四级的路）→ 四级步骤，每级不超过 3 项，每步一块、一个锚点 → 页底订阅 → 页脚。挂在 AI 发展史下，看清还是两条线 |
| 文章页、单条开发日志 | 面包屑 → 标题 → 元信息（文章两组：谁写的、什么时候；我们核对了什么。日志一组）→ 目录（收起）和「我们的判断」→ 3 分钟视频（重点文章才有）→ 正文 → 练习 → 接着读（相关文章、去另一站）→ 更新记录、版权和法务小字 → 页底订阅 → 页脚 |
| 动手 `/build`、项目页 | 苔绿色带（动手：标题、一句话、「怎么做」四步，桌面首屏内全部可见；项目页：说明、状态、产品地址）→ 在做的项目 → 开发日志列表（`#devlog`，日期带年份）→ 页底订阅 → 页脚。三段用不同的版式 |
| 关于 `/about` | 纸色色带 → 阅读版式：我们是谁、为什么做、谁在维护、`#contact` → 页底订阅 → 页脚 |
| 页面不存在 | 一句话说明 → 三站入口的三块小色带 → 页脚 |

每种页面在手机和平板上怎么排，见设计系统「手机和平板：每类页面怎么排」；换站靠顶部导航，分站页面上没有书脊。

每页都要有：顶部胶囊导航、页底订阅和页脚（内容按设计系统「页面外壳」：八个链接，加外观和语言两个分段控件）、加载中、空、出错、离线四种状态的样子。主站的页面用同一个导航组件和同一个页脚组件；/body 由 Veli 实现，导航按 ADR-0003 (b) 的三条约定判（`quality-terms.md` U10）。**订阅的上线开关**关着时：不渲染订阅条和页底订阅，首屏底部原来放订阅的位置换成 RSS 链接，页脚的 RSS 照常；版式要在开、关两种状态下都不留空位、不跳动。

## 5. 三种版式

按可用宽度分档，不按设备型号判断。

| 版式 | 宽度 | 边距 | 首屏 | 卡片 |
| --- | --- | --- | --- | --- |
| 手机 | < 744px | `gutter-phone` | 上下拼接，「动手」圆压在接缝上；整屏只有一个实心主按钮，给「开始训练」 | 单列 |
| 平板 | 744–1179px | `gutter-tablet` | 左右各半，两侧内容全部可见，不倾斜 | 两列；研究的通栏大卡收成一列，行也是一列 |
| 桌面 | ≥ 1180px | `gutter-desktop` | 左右各半，有悬停时可倾斜到 62 : 38 | 三列 |

- **一条栅格**：所有页面的内容容器用同一条公式，写成一个类 `.vc-container`，各页面不另写边距；同一宽度下每个页面第一个标题的左边缘相同，首页两半也对到这条栅格上（公式和各宽度下的数见设计系统「统一栅格」；`quality-terms.md` V6）。`verify_canvas.py` 会量跨画板的左边缘。
- **一份标记**：同一份标记靠媒体查询在三档下都成立，不为手机另写一份。
- **悬停只是增强。** 倾斜、悬停才出现的说明只在 `(hover: hover) and (pointer: fine)` 下生效；触屏上所有入口和说明一开始就可见，点一下直接进入。
- **iPad 是一等公民。** 分屏、台前调度会把窗口变窄，版式随宽度落档；接触控板的 iPad 按桌面处理；横竖屏切换只重算尺寸，不重新加载动效。
- **手机细节**：首屏高度用 `100svh`；内容避开 `env(safe-area-inset-*)`；没有横向滚动（表格和代码块在自己的容器里横向滚动）；主按钮放在拇指够得着的下半屏。
- **字号只用阶梯里的 8 级，另加研究卡的 `metric`**，随档位收紧；每一级用在哪里见设计系统「字体和字号阶梯」。阶梯以外的字号不出现，`verify_canvas.py` 会数字号种类。
- **手机长页不超过 6 屏**（390×844）：超过时条目默认收起、原地展开，或分页，不靠缩小字号和间距（设计系统「手机和平板：每类页面怎么排」）。
- **倾斜时谁跟着接缝走**（桌面 62 : 38）：只有「动手」圆、首屏底部的订阅条（或 RSS 行），它们的中心始终在接缝上，用同一个时长和缓动。胶囊导航居中不动：会从指针下滑走的控件点不中。指针悬停满 `delay-hover-intent`（80ms）才倾斜，键盘聚焦立即倾斜，指针横扫首屏不触发。两半里的标题、导语、按钮不跟着接缝平移，各自贴着自己那一半的栅格线；收起一侧的主标题用 `transform` 缩放，不过渡 `font-size`。跟着接缝走的表面背后比例不变，不能声明 `data-backdrop="motion"` 当玻璃用（`design-bar/references/liquid-glass.md` §0）。首屏的构图（定位句、动效区、静态线稿、矮屏先收什么）见设计系统「首屏构图」；手机矮屏先收两半的第二层入口和一行事实，再收看清一半的说明，站稳一半的那一句说明最后才收，叶与网各不小于 `space-8`（64px）。

### 折叠屏

不另做版式，按宽度落到手机或平板档；折叠、展开不重新加载、不丢状态；v1 不读折痕位置：折痕对齐（浏览器报告了两块屏时首页接缝对齐折痕、「动手」圆和导航移到右半块、文章正文只放一块屏）推到 v2。规则和数值以设计系统「三种版式」里折叠屏一条为准（`quality-terms.md` U13；A8 在 v2 再启用）。

## 6. 阅读版式（文章、开发日志、长说明）

阅读体验按「手机上一口气读完」来排。

- **行长和字号**以设计系统「字体和字号阶梯」为准（中文和英文正文同一个字号，版心和行高不同；`quality-terms.md` A6）。宽屏上不拉宽正文，多出的空间留白或放侧注。
- **段距**：段距接近一行的高度（`space-5`）；标题和上一段之间的距离是它和下一段之间的两倍，让标题贴近它管的内容。
- **字体**：中文正文用苹方和 Noto Sans SC；看清的标题用衬线（New York、宋体、Noto Serif SC），正文仍用无衬线，长文更好读；代码用 `font-mono`。
- **中英混排**：盘古之白由内容负责（`velicoach-content` 第 6 节），版式不靠 CSS 补空格；可以渐进地加 `text-autospace: normal`。标题用 `text-wrap: balance`，正文用 `text-wrap: pretty`，避免末行只剩一个字。
- **标题**：最多三级，字号取阶梯里的档。
- **代码块**：等宽，字号按设计系统；不自动换行，在块内横向滚动；右上角有「复制」按钮；标明语言。行内代码用浅底，不加边框。
- **表格**：放进可横向滚动的容器，首列固定；数字列右对齐并用等宽数字（`font-variant-numeric: tabular-nums`）。
- **图**：用 figure 和 figcaption；图注写清楚这张图说明什么、出处是哪里；图片按宽度自适应，给出宽高比避免跳动。
- **引用**：左侧 2px 强调色竖线，不用大引号装饰；引用原文时标明出处。
- **目录**：超过 2000 字的文章有目录，放在标题区下面，默认收起，三种版式都是。桌面上的常驻目录这一版不做（`docs/uiue/decisions.md` 2026-11-12「本轮不做」）。
- **等宽字体只排数字、拉丁字母和符号**：年份、日期、提交号这类等宽元素里出现中文时，中文落到正文字体，不加字距（设计系统「字体和字号阶梯」）。
- **3 分钟视频**：放在正文之前；播放条用厚玻璃；有字幕和文字稿入口。
- **文末**的顺序：练习 → 接着读（相关文章最多三篇、去另一站的入口，含「今天的训练」）→ 更新记录、版权和法务小字；不堆成推荐墙。

### 看清的页面

看清的气质是「工程师的书房：极简、克制、有品味」，来自陈皓的技术判断（学方法、没有捷径、知识要能被检索和更新），不照搬任何网站的样式。细则见设计系统「看清的气质」。做页面时：

- 首屏是一条墨色色带：站名、一句描述、两条内容线的分段控件（AI 发展史、人机协作，各有自己的地址）、到学习路径的入口，底部是这一页的数据图（时间尺或套叠图：只用 token 颜色，不加动效，有文字等价物）；没有主图、动效和插画，不加载 three.js。
- 里程碑和开发日志一行一条，整行可点（一个链接包住，点按区域 ≥ 44px），第二个去处放在行下面；人机协作的文章、工具、技能用整张可点的卡，第一行标类型、语言、有没有 3 分钟视频；不用缩略图。
- AI 发展史是按五个时代分段的时间线：里程碑默认一到两行、原地展开；点距随年份间隔变（同一时代里相差 10 年的两条，点距不小于相差 1 年的 1.5 倍）；时代段头不吸顶，跳转用桌面右栏的时代索引或手机、平板的时代跳转胶囊。细则见设计系统「时间线」。
- 学习路径每步一块：桌面和平板是能扫读的行，手机上下排；不用宽表格，不横向滚动（设计系统「学习路径步骤块」）。正文里的表格只用横线。
- 引用用脚注；桌面版式把脚注放到正文右侧作侧注（`sidenote-width` 240px），手机和平板放回文末。
- 每篇标题下一行：发布日期、「适用于」（模型、版本）、最后核对日期；有原文日期时也显示，和发布日期分开标（哪个是本站发布的、哪个是原作发表的，`docs/standards/quality-terms.md` T3）；改过的在文末列更新记录；每个小节有锚点；文末有「指出错误」的入口。
- 学习路径每一步显示要花的大概时间、「怎么检验」和最后核对日期，里程碑也显示最后核对日期（quality-terms T3）；文章末尾的练习可以一步带到动手一站。
- 字体只用衬线标题、无衬线正文、等宽代码三种；颜色只用墨、纸、朱砂，朱砂只给链接和「当前所在」，链接加细下划线。
- 每种语言一个 RSS 源，入口在页脚，不按内容线分；不弹窗，读文章不需要登录。
- 文章页首屏只有文字，不依赖脚本也能读；除图片外一篇文章传输不超过 150 KB。

## 7. 组件与位置

- **胶囊导航**：高 `nav-height` 52px；背后是平涂底色时用实色面，滚动时压过正文用玻璃；三档都居中贴顶，倾斜时不动；滚过首屏色带底边时从实色面换成玻璃，过渡用 `duration-base`。内容从左到右：站标（叶子加 Velicoach 字样，窄屏只留叶子，320px 宽也不收）、三站入口（站稳、看清、动手；Body、Mind、Build）、语言切换。三档都不用汉堡菜单。**每个页面顶部只有这一条导航**：v1 不做本站操作条，不叠两层玻璃。
- **语言切换**：导航最右端的分段控件「中文 | EN」；手机导航窄于 360px 时收成一个按钮「中 / EN」（折叠屏半屏窄于 860px），当前语言加粗。选项用语言自己的名字，不用国旗；两个选项是指向对应语言版本的链接，带 `hreflang`，当前语言标 `aria-current`；切换后到同一页面的另一语言版本。支持三种语言后再换成地球图标加菜单。
- **首页点进一站时的过渡**：点击后另一侧收成窄条，再进入分站；这个过渡是首屏的一部分，分站页面上没有这条窄条。
- **按钮**：主按钮 50px 高、胶囊形、实色加边缘光，一个区域只有一个；首屏左右对开时两半各有一个主按钮，上下拼接时（手机）整屏只留一个，给「开始训练」。次要入口用文字链接或描边。可点元素至少 44px（`size-tap-min`；页脚链接、面包屑、整行可点的行、文内独立成行的链接都算，小字链接用伪元素把点按区域撑大，不改版式）；文字一行放下。按下内容下移 1px，不缩放；加载中宽度不变。层级、状态和出处见 `references/buttons-and-glass.md`。
- **卡片**：用 `shadow-card`，不用玻璃；整张卡可点，标题是链接文字。数字卡（研究卡）、强调卡、项目卡、三站入口各自的结构见设计系统「组件」；研究卡按证据可信度分级：可信度高或中、有外行读得懂的数的做通栏大卡，放大数字；低和很低的，或者只有效应量的，降成行，数写进方法一行；每项都带四格可信度刻度和文字，每张卡带 `data-credibility`（设计系统「研究卡」；`quality-terms.md` T8，`npm run check:research-metric`）。
- **订阅**：首屏底部一行订阅条，点「订阅」后邮箱框原地展开，填完提交，两步；每页页脚前面另有页底订阅。告知只有一句，全站同一个写法，带隐私政策链接；提交即订阅，提交后原地显示结果，不跳页。写法、状态和订阅的上线开关关着时的样子，见设计系统「订阅」。

## 8. 玻璃

- 玻璃只给背后会变的那一层（动效、视频、吸顶时滚过的正文）；背后是平涂底色时用实色面（`surface-solid`、`surface-ink`），玻璃在那里只是一块灰。正文和卡片不用玻璃，主按钮不用玻璃。
- 做法用 `design-bar` 的液态玻璃：表面只加 `lg` 和一个状态类（`lg-on-dark` 浅色字），写上 `data-backdrop`（motion、video、scroll）说明背后是什么，要透镜的加 `data-lens`；吸顶的导航不挂透镜。本站哪些表面用、哪些不用，见设计系统「玻璃材质」表；做法和数值见 `design-bar/references/liquid-glass.md`。
- **声明要真**：`motion` 只给动效的粒子真会从后面经过的表面；跟着接缝移动的圆、导航、订阅条背后比例不变，用实色面。`scroll` 只给吸顶的导航。拿不准时用 `capture_motion.py --probe <表面>` 量一下。
- **不做苔绿玻璃**：品牌色玻璃要浓到 50% 以上字才读得清，那就是实色。动手页首屏的导航用苔绿实色 `nav-moss`，滚到纸色正文上换成普通的 `lg`。
- **骑在接缝上的控件用两色焦点圈**：一侧纸色、一侧墨色时，贴着控件一圈墨上白、外面一圈焦点蓝，哪一侧都有一圈 ≥ 3:1（`.orb:focus-visible`）。
- **吸顶条和通栏的模糊**：吸顶玻璃统一用 `--lg-blur-scroll`（20px），边缘渐隐；通栏（宽度超过约 600px 或左右贴边）不画径向高光和内光，底色取背后的主色，对比度按最亮的一段正文算。
- **玻璃不叠玻璃，一页只有一条吸顶栏**：吸顶的只有导航；它下面不再吸任何一条（时代段头、目录、操作条都不吸顶），玻璃卡片里不放玻璃按钮。
- **「动手」圆是实色**：它跟着接缝走，背后永远是两块平涂，用苔绿实色加斜面阴影（`shadow-bevel`）和一圈 1px 亮边（`vc-orb-ring`，两种主题都画），悬停叠 14% 白，按下换内凹阴影、内容下移 1px；不挂玻璃。
- **状态**：每个可点的玻璃控件有悬停（底色提亮约 14%）和按下（浓一档）两条规则，不叠 `vc-state-*` 灰色层；实色按钮才用状态层（`references/buttons-and-glass.md`）。
- 玻璃上的文字按最差的背景算对比度，悬停、按下也算，至少 4.5 : 1；不够就提浓度，不降字的透明度。
- 降低透明度、强制颜色、不支持背景滤镜时换成同色实色面。

## 9. 浅色与深色

- 全站默认跟随系统（`prefers-color-scheme`），系统切换时立刻跟着变；读不到时用浅色。
- 页脚里有「自动 / 浅色 / 深色」（账号菜单里的同一组是 v2；v1 只在页脚切换）；按设备记住（本机键名 `vc-theme`，语言是 `vc-lang`，同时写进作用域为 `.velicoach.com` 的 cookie，读时 cookie 优先；本机存储和 /body 共用，cookie 让子域名上的 WordS 读得到），`<head>` 里在绘制前设好主题，刷新不闪；设 `color-scheme` 和按主题的 `theme-color`。
- 品牌色带（首页两半、看清和动手的首屏）保持各站颜色，深色下降亮度或提一档，不换色相；色带以下的阅读区、列表、卡片、表单都跟随主题。深色下相邻的大色面要分得开：品牌两半 ≥ 1.8:1，墨色色带和强调面对页面底 ≥ 1.3:1 并加 1px 描边（数值和 token 见设计系统「浅色与深色」）。
- 颜色只用带浅色、深色两个值的 token；每个页面截浅色、深色两套图，两套都过 WCAG 2.2 AA。

## 10. 动效：「叶与网」

- 首页主动效是方案 C「叶与网」：Veli 的叶子由几千个点组成，桌面上首屏向右倾斜时散成一张网，向左时长回叶子；每个点的颜色取决于它落在哪一侧。没有悬停的设备上跟着呼吸周期（`duration-breath`）自动往返。
- 动效区占首屏上半，叶在左、网在右，「网」是节点加连线；动效不可用（无 WebGL、减弱动态效果、还没加载完）时是同一构图的静态线稿，不留空。同一屏只有一个主动效。
- 技术：three.js 的 WebGPURenderer 加 TSL，自动回退到 WebGL2；都不可用时显示静态画面。首屏文字绘制完再加载 three.js，不拖慢最大内容绘制。
- 预算：中端手机每帧不超过 4 毫秒，手机上粒子数减半；滚出视口或切走标签页时暂停；帧率持续低于 40 时把像素密度降到 1 倍。
- 系统打开「减弱动态效果」时只画一帧静态画面，倾斜也不做过渡。
- **订阅成功**：「已订阅」前面的叶子把两条叶脉画一次，`duration-base`（240ms）、`ease-out`，只播一次；减弱动态效果下直接显示画好的叶子。全站完成一件事的反馈只有这一种，不加彩纸和声音。
- **暂停按钮**在动效区的角上、贴着它控制的动效（桌面和平板在右下，手机在左下），仍是 `tap-min` 的实色墨面。
- 界面过渡的时长和缓动只用 `duration-*` 和 `ease-*` token。

## 11. 双语版式

- 英文通常比中文长 30% 左右：不固定按钮和标签的宽度，用伪语言（加长 35%）截图检查，不截断、不溢出。
- 每页声明 `lang`；英文页面在 `/en/` 下，与中文页面一一对应并互相声明 `hreflang`。
- 英文标题用 sentence case，不全大写；字距沿用设计系统的英文设置。
- 同一个组件中英两版的高度可以不同，版式不能因此错位：列表和卡片按内容撑高，不写死高度。

## 12. 无障碍

- WCAG 2.2 AA：文字对比度至少 4.5 : 1；可点区域至少 44px；只用键盘能完成全部操作，Esc 让首屏回到五五分。
- 焦点环用 `vc-focus`，2px，向外偏移 2px；不去掉焦点样式。
- 系统字号放大到 200% 不截断；不只靠颜色表达状态。
- 动效画布对读屏软件隐藏；图表和插图有文字说明；短片有字幕和文字稿。

## 13. 交付检查

1. **多宽度截图**：覆盖三档和各档边界，375、744、820、1024、1180、1440 六个宽度，浅色、深色、伪语言各一套；手机和 iPad 再各截一张横屏。
2. **设计检查**（`design-bar` 技能的脚本）：
   - `check_page.py <页面路径或 URL> --out <报告目录> --dark --widths 320,375,744,1180 --targets-up-to 1180 --project-config docs/uiue/design-bar.json`（可点区域三种版式都量，`quality-terms.md` A2）
   - `npm run check:tokens`（#22 加；跑 `lint_tokens.py src --project-config docs/uiue/design-bar.json --tokens <token 文件>`）：不能有写死的颜色、字号、间距、圆角和时长。
   - 改了画板：`verify_canvas.py <画板目录> --out <报告目录> --themes light,dark,pseudo --project-config docs/uiue/design-bar.json`（本站的色面门槛 1.8:1 在 `docs/uiue/design-bar.json`，画板在仓库外时脚本找不到它，所以命令带上；`docs/standards/pipeline.md` §7），修到结论为 done；先核对报告里每块画板「查的视口」和画板的设计尺寸对得上（流式页面自动加查 390、320 宽）。
   - 动效和玻璃的证据（标杆卡 P4）：`capture_motion.py <首页画板> <输出.png> --state '{"lean":"body"}' --hover <x,y> --blob <id>=<文件>`，四帧：倾向站稳（叶）、倾向看清（网）、`--reduced-motion` 静止帧、`--no-webgl` 兜底（加 `--expect <兜底元素的选择器>`，证明兜底画出来了）；每个声明 `motion` 的玻璃加一次 `--probe`。吸顶玻璃截「正文一行字正好从导航文字后面滚过」的那一张（画板用属性把内容往上移，`liquid-glass.md` §7），在图上量对比度。
   - 内容模型的字段都画出来了：`coverage.py --canvas <画板目录> --data <研究卡数据.json> --skip-fields id,topic`。
3. **去 AI 味**：按 `unslop` 的信号清单过一遍；和设计系统冲突时以设计系统为准。
4. **偏好 cookie**：写入的字符串（`vc-theme`、`vc-lang` 各一个，`Domain=.velicoach.com; Path=/; SameSite=Lax; Max-Age=31536000`、不带 `Secure`）和读取顺序（cookie、本机存储、系统偏好）用单元测试（`node --test`）查，不依赖域名，上线前就能跑；预览部署在 `*.vercel.app` 下，浏览器不接受这个 cookie，预览上查不了 cookie，只查本机存储和 /body 的来回切换；cookie 本身在真实域名上查，步骤写在 `docs/delivery/launch-runbook.md` 切换后第 13 步。票的验收照这条写。
5. **状态与降级**：加载中、空、出错、离线；关闭动效、降低透明度、减弱动态效果、无 WebGPU。
6. **性能**：手机 75 分位 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1。
7. **步数**：按 PRD 的步数表逐个场景数一遍，每步标意图步或可删步（v1 只数未登录；登录后的一列是 v2）。
8. **真机**：iPhone、iPad、Mac Safari、一台中端 Android 手机各走一遍关键路径。
9. 报告放进 `docs/uiue/reviews/<日期-主题>/`；交付时说明做了哪些体验决定和理由，记进 `docs/uiue/decisions.md`。

## 14. 改进规范

一条修改意见代表一类问题：找出背后的原则，改完所有同类页面和组件，再把原则写回设计系统（规则或 token）、本技能或检查阈值，并在设计决定记录里记一笔。不留下探索用的临时代码、未使用的样式和组件变体。
