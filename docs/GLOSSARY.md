# 术语表

中英文案、代码命名、文档都按这张表用词。仓库术语表是唯一来源，PRD 不再摘录，只指到这里。

**原则**

- **用行业通用、用户已经熟悉的词。** 有通行中文译名的用中文（智能体、提示词工程、上下文工程）；还没有通行译名的保留英文，第一次出现时带一句白话（Harness 工程、Loop 工程、Graph 工程）。
- **谨慎造词。** 表里没有的新名字，先查业界怎么叫；确实要新起，先加进这张表再用。
- **一个概念一个词。** 不为了变化换同义词。
- **例外**：三个站名站稳、看清、动手就是品牌口号「先站稳，再看清，然后动手」里的动作；品牌和产品名 Velicoach、Veli 第一次出现时带一句说明。
- 对外文案和内容按这张表写。内部文档里说到我们自己的开发 agent（写代码、跑流水线的那些）可以写 agent。

体验规则里的三个词（前两个的定义以 `design-bar/references/ux-canon.md` 第 1 节为准，这里写本站的清单；法定步是本站补的，PRD 第 4 节「步数预算」）：

- **撤不回的动作**：撤销窗口内没法把外部世界恢复原状的动作，按效果有没有外泄判（发出去了、别人看到了、用户照着做了），不按界面上有没有撤销按钮判。本站有：分享和投稿公开、删除账号、付款（如果以后有）；Veli 的清单在它的工作手册 §3.2。意图只来自用户：设置（如自动续费）、明确指令（如「分享这篇」），或一次单独的确认；Agent 不主动发起。写明的例外只有一个：每周订阅邮件的发送，产品负责人预先授权，每期有取消窗口（PRD「授权与确认」表）。
- **意图步**：为一个撤不回的动作确认意图的那一步，每个动作最多一个，写清后果；不计入步数预算，也不许省。
- **法定步**：法律要求的同意屏，例如 Veli 新用户的年龄与同意页。它不是为撤不回的动作确认意图，所以不是意图步；计入步数预算，也不许省。
- 意图步和法定步以外的步骤都是可删步，超预算只删可删步。

协作用语（只在文档和票里用，和 Veli 仓库同义；定义见 `docs/standards/pipeline.md`）：关口（阶段之间的出口检查）、车道（站点、内容两条，按路径分工）、冷评审（没看过制作过程的新 Agent 做的评审）、票推进器（推进一条车道的定时任务）、观察者（从外面看整条流水线的 Agent）、运行锁、交接评论、集成分支（`feature/v1`）、决策简报（要产品负责人合并的 PR 说明最上面的七项：要你判断什么、背景和事实、为什么要你、选项和后果、建议和理由、风险和怎么撤回、怎么回；`pipeline.md` §5.2。只指这一种，别的「简报」说里程碑简报、两行说明）。

## 口语和转写错误

用户原话只进 `docs/requirements/timeline.md`，原样保留。其余文档、技能和对外文字用书面表达和这张表里的标准术语（`AGENTS.project.md`「不能越过的线」第 1 条）。`npm run check:voice` 按下面三份清单检查；`check:terms` 也读转写错误和允许的说法这两份，两边用同一张表。

- **口语标记**：口头禅、语气词、重复。出现就改成书面表达。只在引号里单独写出一个标记（例如「嗯」）算点名，不算使用。方括号里的只算独立出现、后面紧跟停顿标点的语气词：「[啊]」拦句首或停顿处单独的「啊」，不拦「真好啊」；英文只收不会撞上正常句子的「[um]」，不收 you know、uh 这类会出现在正式英文里的词。
- **允许的说法**：含清单里的词、但本身没错的写法：书面词组（也就是说）、点名错字的说明（不是阀值）、有意提到旧说法的固定写法（搏击等对抗性运动）。两份检查共用这一份。
- **转写错误**：语音识别或打字出的同音字、错别字、误识别的名字。放在引号里照样报：点名错字要写进允许的说法。拿不准的名字列给产品负责人确认，不猜；确认之后加进来。
