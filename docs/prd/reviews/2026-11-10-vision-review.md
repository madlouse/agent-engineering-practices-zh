# 主站 PRD v1.2 的愿景评审

> 2026-11-10，主会话。产品负责人要求（`timeline.md` 第 87 条）：全面读懂用户原话和项目愿景，逐个功能点论证 PRD 的设计能不能达到这个效果，可以做任何删减或修改，用最简单的方式让用户最易用、最信任；以后由 Agent 长期维护。
>
> 读过的材料：`timeline.md` 全部 86 条原话、总体方案第 95 版、PRD 第 306 版全文、ADR-0003、ADR-0004、46 张站点票和 9 张内容票的清单。本文是论证和决定；PRD 按本文改成 v2.0 后，本文存档。

## 1. 愿景读成什么

把原话按时间读下来，愿景只有四句话，后面所有判断都拿它们当尺子。

| 愿景 | 原话 |
|---|---|
| **一个路口，两件最重要的事。** AGI 让人兴奋也让人不安。每个人要做的是两件事：身体练强；学会和 AI 一起做事 | 第 28、31、32 条 |
| **陪练，不是媒体。** Velicoach 是 AGI 路上的陪伴者和引路者：陪人练、陪人学、陪人动手，成为 builder 是最重要的一件事 | 第 30、31、34 条 |
| **见证。** 记下 AI 是怎么走到今天的（里程碑、路线怎么变），也记下我们自己怎样和智能体一起把东西做出来 | 第 24、28、64 条 |
| **健康 + AI + 教育，长期经营。** 一个主站，下面挂产品；用 AI 不断做出产品，吸引人，交付价值；以后由 Agent 长期维护 | 第 34、87 条 |

体验上的要求同样清楚：一站、一键、一秒（第 51、77 条）；看图标和位置就会用，少放字（第 77 条）；极简、克制、偏工程的品味（第 62 条）；对外只放正式版，事实有出处（第 36 条）；方案坚持最小必要（第 55、69 条和账号里的偏好）。

## 2. 用什么尺子量

每个功能点问五个问题，答不上来就删或推后：

1. **它直接服务哪一句愿景？** 服务不到的是装饰。
2. **没有它，三类用户的主线走不走得通？** 主线只有三条：开始训练、读一篇、看我们怎么做。
3. **它要不要人每周来一次？** 以后是 Agent 长期维护，要人定期出场的环节会先断。
4. **它让我们多保管一份别人的数据吗？** 少保管一份，就少一类出事的可能，也更容易让人信任。
5. **现在的内容量撑不撑得起它？** v1 上线时是 5 篇文章、三十来个里程碑、十来个学习步骤。

## 3. 总体结论

**方向是对的：三站叙事、双侧首屏、「叶与网」、看清的两条内容线和开发日志，都直接来自原话，保留。问题在重量：PRD 把最多的工程量花在了离愿景最远的地方。**

| 现状 | 数字 |
|---|---|
| 功能点 | 29 个，P0 有 22 个 |
| 订阅的验收细则 | 15 条，另有一个独立数据库、6 张 `risk:high` 的票、3 件产品负责人要办的事 |
| 自定统计事件 | 11 个 |
| 挡住上线的外部事项 | 律师、持证教练、发信域名、订阅数据库、通讯地址、联系邮箱、Vercel 套餐、Veli 的 /body |
| PRD 篇幅 | 约 9.2 万字节，Agent 一次读完要占掉很大一块上下文 |

PRD 自己写了「最大的风险是内容」，但 46 张站点票里，订阅、统计、搜索和跨仓库的外壳包占了约 18 张，其中 7 张是 `risk:high`。上线被八件外部事项卡住，其中没有一件是「内容够不够好」。

**改法是三件事：把主线做到最好；把离主线远的东西删掉、换成现成的服务或推后；把要人定期出场的环节减到最少。**

## 4. 八个结构性改动

### 4.1 站稳页 /body 由主站实现，撤掉外壳包

- **现状**：/body 由 Veli 仓库实现（第 80 条的选择）。为了让它和主站长得一样，主站要把导航、页脚、书脊、订阅条打成一个包，Veli 用固定版本引入；研究卡数据也跟着这个包发（ADR-0003 (b)）。
- **问题**：站稳是三站之一，是主站叙事的三分之一。把它放在另一个仓库、另一个框架里，换来的是一个要发版本的包、两边的版本同步、研究卡数据的两份副本，以及「Veli 的外壳最多落后一个版本」这种本来不该有的状态。用户看到的三站也可能不一致，违反「一站」。
- **改成**：/body 是主站的一个内容页，放三样东西：为什么是肌肉（研究卡）、威利怎么陪你、开始训练。数据、设计系统和导航都是主站自己的。Veli 只管它自己的产品：/app、/auth、/pricing、法务页。
- **换来什么**：外壳包、版本同步、`research.json` 的共用和版本校验全部不需要；首页「开始训练」的落点不再等 Veli 改 /body；Veli 仓库少一批为主站做的活。
- **代价**：Veli 仓库现有的 /body 落地页下线，转给主站；Veli 的 #185、#101 改范围。这是跨仓库的结构变化，ADR-0003 要修订。

### 4.2 订阅用发信服务自带的名单，不建自己的数据库

- **现状**：主站单独建一个 Supabase 项目存名单和同意证据，发送前同步到 Resend，退订、退信、投诉由回调写回，自己签退订令牌、自己做退订页（ADR-0004）。
- **问题**：这是全站最重、风险最高的一块（6 张 `risk:high` 的票、一条迁移工作流、两个连接串），做的却是发信服务本来就有的功能。它还让我们多保管一份邮箱名单。
- **改成**：订阅接口只做两件事：频率限制，然后把邮箱连同语言、来源、表单文案版本写进 Resend 的联系人（联系人支持自定属性）。名单、退订、退信和投诉的停发都交给 Resend；每周邮件用 Resend 的群发。主站不存邮箱。
- **换来什么**：不要订阅数据库、迁移工作流、回调接口、退订页和令牌；`risk:high` 的票从 6 张降到 1 张；「订阅的细则」从 15 条降到 6 条；产品负责人少办两件事（#40、#67）。
- **代价**：名单在 Resend 里，换服务商时要导出；退订页用 Resend 的页面，样子要按它允许的范围调。修订 ADR-0004 时逐条核对 Resend 的能力（一键退订邮件头、中英两种退订页、关掉追踪）。

### 4.3 订阅不挡上线

- **现状**：订阅是 P0，律师的书面确认、发信域名、通讯地址都挡着上线。
- **改成**：订阅表单由一个开关控制。律师意见和发信域名到位了再打开；没到位时页面上不出现订阅（没上线的功能不在对外页面出现），订阅的位置放 RSS。上线只取决于内容和主线。
- **换来什么**：上线不再等律师和域名配置；RSS 先承担「每周回来」的作用。

### 4.4 学习路径单独成页，看清回到三条线

- **现状**：学习路径「挂在 AI 发展史下」，是 `/mind` 页面里里程碑下面的一段，靠锚点到达。
- **问题**：教育是愿景的三根柱子之一（第 28、87 条），第二类用户最想要的就是「一条可靠的学习路径」，原话里它本来是单独的一条线（第 41 条）。现在它排在三十来个里程碑后面，没有自己的地址，搜索引擎也只能收到一个锚点。
- **改成**：看清三条线，各有地址：`/mind`（AI 发展史）、`/mind/learn`（学习路径）、`/mind/collaboration`（人机协作），同一个分段控件切换。里程碑照旧链到对应的学习步骤。
- **换来什么**：「我该怎么学」一步到达；「Karpathy 课程」这类搜索有一个真正的页面可以落。

### 4.5 搜索、书脊、本站操作条、类型筛选、项目页：删或推后

| 项 | 为什么现在不要 | 以后 |
|---|---|---|
| 搜索（F26，含 ⌘K、搜操作、`?q=`） | 5 篇文章、三十来个里程碑，列表一眼看得完；它是 P0，带着索引、浮层、四种状态和 1 秒的量法 | 文章超过 30 篇时做 |
| 书脊（F08） | 胶囊导航每页都在，书脊是第二套导航；在阅读页上占宽度，和「看清」内容为主的气质冲突。首页点进一站时另一侧收成窄条的过渡保留，它是首屏的一部分 | 不做 |
| 分站滚过首屏后的本站操作条 | 第三套顶部控件 | 不做 |
| 里程碑的类型筛选（`?type=`） | 按五个时代分组已经够用；筛选带来地址、锚点清空等规则 | 里程碑超过 60 个时做 |
| 项目页 `/build/<项目>` | v1 只有三个项目，项目页就是日志列表的一个筛选 | 动手页上按项目筛，原地切换 |
| 首页 builder 区（F04） | 和动手页重复 | 不做 |
| 首页「今天的训练」快捷入口 | v1 不读登录状态，它和「开始训练」去的是同一个地方 | v2 读登录状态后再放 |
| 折痕对齐（Viewport Segments） | 只有少数浏览器默认支持；版式按宽度已经覆盖折叠屏 | v2 |

### 4.6 统计从 11 个事件减到 4 个

原话是「先建立起监测指标就行」（第 45 条）。衡量指标表里的六项，各自最少需要什么：

| 指标 | 需要 |
|---|---|
| 访问来源 | 页面访问统计自带 |
| 首页 → 三站 | 三站首页的访问量和来路，页面访问统计自带，不用事件 |
| 订阅数 | Resend 的联系人数 |
| 主站 → Veli | `start_training` |
| 完读、完播 | `article_complete`、`video_complete` |
| 订阅提交 | `subscribe` |

保留这四个事件。语言切换、订阅失败原因、搜索、页面状态、关键路径步数这七个删掉：步数在端到端测试里已经逐条数过，线上不再重复采。

### 4.7 每周内容由 Agent 负责到底，人只管三类事

- **现状**：每周选题、审读、定稿、抽查、订阅邮件定稿都写着「人负责」；内容定稿的 PR 归产品负责人合并。
- **问题**：以后由 Agent 长期维护（第 87 条）。每周五步都等一个人，这个节奏撑不过一个月，PRD 的风险表自己也写了「内容生产跟不上每周节奏」。
- **改成**：Agent 选题、生产、独立评审、发布；产品负责人每周收到一份摘要，可以随时撤下任何一篇。要人出场的只有三类：新开一个栏目或一条内容线；训练指导（要持证教练）；法律、付费和对外承诺。
- **边界**：质量先于节奏。一周没有达到标准的文章就不发，邮件改发里程碑更新和开发日志，不凑数。
- **这一条要产品负责人明确同意**：它扩大了 Agent 自己的权限，不能由 Agent 自己定。

### 4.8 研究卡的把关换成「出处由独立评审核对」，持证教练只审训练指导

- **现状**：四张研究卡和每封邮件里的「一练」都要持证教练审核，挡着首页和每周的邮件。
- **问题**：研究卡是在转述系统综述的结论，要核对的是「数字和原文对不对得上」，这是出处核对；教练该审的是「怎么练」。
- **改成**：研究卡每条给出处，由独立的内容评审对着原文摘要核对数字、研究类型和样本量，对不上不发。邮件里的「一练」不写训练动作，只放一句有出处的话和「今天的训练」的入口，训练内容都在 Veli 里，按 Veli 的规矩由教练审核。
- **另外**：第四张卡「外形」换掉。它只讲男性的吸引力，和 Veli「讲力量、不讲身材」的规则相冲，画板上也没有照它画。换成「脑力」：运动和认知的关系，正好把站稳和看清接起来。出处由内容票核实，核实不了就只放三张。
- **这一条也要产品负责人明确同意**：它放宽了健康内容的一道把关。

## 6. 非功能需求和文档本身

| 项 | 改法 | 理由 |
|---|---|---|
| 步数预算、行为设计、八种「少一步的做法」 | PRD 只留步数表；做法和理由留在设计系统 | 这些已经写在设计系统里，PRD 重复了一遍 |
| 折叠屏的验证 | 只留按宽度截图；去掉两种模拟器上的折叠展开 | 版式按宽度决定，没有折叠屏专属的代码 |
| 社交分发 | 中文、英文各先做一个产品负责人实际在用的渠道 | 九个渠道都要人去发；分发包按实际在用的渠道生成 |
| 每周节奏 | 4.7 | — |
| 决定记录、修订记录、对抗评审记录 | 移出 PRD，各放一份文件 | PRD 只写「现在是什么」，历史单独存 |
| PRD 篇幅 | 目标 4 万字节以内 | Agent 每次做需求都要读它 |

没有改的：性能预算、无障碍、国际化、隐私（统计不写标识符）、版权规则、设计系统。它们直接对应「一秒」「信任」和原话，标准也都能判对错。

## 7. 改完以后的 v1

- **首页**：双侧首屏和「叶与网」；为什么是现在；最新一篇。
- **站稳 /body**（主站）：为什么是肌肉、威利怎么陪你、开始训练。
- **看清**：AI 发展史、学习路径、人机协作三条线；文章页；迁入的 5 篇。
- **动手 /build**：怎么做（四步）、在做的项目、开发日志。
- **全局**：导航和语言、页脚、关于（含「谁在维护」）、外观、RSS、SEO、四个事件的统计、三种状态页；给智能体读的版本。
- **订阅**：有开关，条件到位后打开。

上线只取决于两件事：这些页面做完并通过关口四；首批内容达到标准。

## 9. 要产品负责人决定的

大多数改动是删减和简化，按「最小必要」直接做。下面四项推翻了已经确认过的决定，或者改变了谁有权做什么，要产品负责人明确点头：

1. **站稳页 /body 由主站实现**（4.1）。推翻第 80 条的选择。
2. **订阅用 Resend 自带的名单，主站不存邮箱**（4.2）。推翻已采纳的 ADR-0004。
3. **每周内容由 Agent 定稿发布，产品负责人事后可撤**（4.7）。扩大 Agent 的权限。
4. **研究卡由独立评审核对出处，持证教练只审训练指导**（4.8）。放宽一道健康内容的把关。
