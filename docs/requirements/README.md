# 这个目录

- [timeline.md](timeline.md)：本会话里留得住的用户原句，按时间排。
- [summary.md](summary.md)：按主题汇总。不代替原句。
- [trace.md](trace.md)：需求追踪。第 28 条起（Velicoach 主站）每条原句怎么理解、落在哪、状态。
- [attachments/](attachments/)：用户随消息发来的截图。

## 收录一条输入

产品负责人的每条输入分三栏落地（`AGENTS.project.md`「不能越过的线」第 1 条）：

| 栏 | 写在哪 | 写法 |
|---|---|---|
| 原话 | `timeline.md` 一节，编号、日期和时间（ET） | 原样保留，口语、错别字、同音字都不改；只有残段就写残段，不补写 |
| 规范表述 | `trace.md`「理解与裁决」一栏的第一句 | 用产品经理的书面表达和术语表的标准术语，把原话重写成一句可执行的要求；同音字和转写错误按语义改正，拿不准的名字列进这一栏，等产品负责人确认 |
| 举一反三 | `trace.md`「举一反三」一栏 | 这条输入代表哪一类问题；全仓库同类位置在哪（文件、规则、技能、检查）；各改了什么，或为什么不用改 |

落地前先按金字塔原理定位层级和维度，找已有的相关规则，合并或升级，不另起重复的一条；能写成检查的写成检查。第 84 条起「举一反三」一栏必填（`npm run check:voice` 查），之前的条目不补。
