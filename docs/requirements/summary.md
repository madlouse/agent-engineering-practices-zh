# 要求汇总

给以后改这个站的人。每条后面的数字是 [原句](timeline.md) 的编号。原句和这里不一致时，以原句为准。这里不把残缺的第 1 条补全，也不把没说过的要求加进来。

## 站点与文章

- 做一个 Agent 工程落地技术博客的中文版。先把点名的材料收进来，再提交到 GitHub。（1。篇名在留下的原句里看不全。）
- 加上 Dan Koe 这篇，讲 Agent 与生活，中文和英文都要有。（2）
- 先有博客框架，再按这个结构往里放文章。（5）
- 官方中文不改写。原文里的图标、视频，以及无法翻译的部分，都留下。内容要 100% 包含原文。（8）
- 没有官方中文时，不用 kai。翻译和排版参考 Fenng 的中文技术文档风格。（4）

## 读者看到的样子

- 页面和代码块都要做视觉检查，一件一件做。（6、7）
- 不只要界面。布局、名字也要考虑。主页要有高级感，并配上图片。（9）
- 「落地实践」这个名字太土。名字要面向 AGI 之后，人和 agent 一起协作、生活、探索、实践、学习。（9）
- 「同席」听起来奇怪，要重新想名字。（20）
- 导航里的「体例」看不懂，而且奇怪。（21）
- 文章正文以外的文案，去掉制作过程，去掉 AI 味。这是给读者的最终版本：好懂，不造词。专业术语可以留。（22）
- 右上角做全站的中文 / 英文切换，不只在某一篇里。（9）

## 文前短片和旁白

- 每篇文章前面放一条大约 3 分钟的剪辑动画，用费曼学习法把精华讲清楚。（8）
- 这必须是一条 shorts 视频，不能是停在一句文案上的画面。（12）
- 图、表、动画都要表达文章的核心，让人停下来也能看懂，比读长文更容易记住，精华不漏。要能播放，要能缩放。（13）
- 做短片前先找开源动画 skills，能直接用的就用，再加自己的规范。（13）
- 旁白要接近真人。中文一条，美式英文另一条。用来源可以是开源方案，也可以是 agent harness 里已经带的，但文件要真的留下。（11）

## 做法

- 文章处理过程要做成 skills，放在项目里。`AGENTS.md` 能找到并调用。不同步骤的 skills 可以组合，而且要打磨过。（8）
- 用 unslop 打磨。不单打磨界面。（9）
- 整条流水线是多份 skills 合在一起，用 poteto 的 skills。（16）
- 没做完的拆成多个 issue，逐个跟。可以用 pstack。（15）
- 需求先写 PRD，再写界面，再写代码。相关的 skills 也走这个顺序。（9）
- 用户的原话按时间留在 `docs`，以后用它检查做到了没有。（9、23）
- 可以部署到 Vercel 或 Cloudflare。域名用 velicoach.com，另取一个二级域名。（9）
- 先把已经做出来的提交到本地 git，再继续未完成的项。（19）
- 没做好就继续，不要停在半成品上。（14）
- 「每小时」只是当时那个循环任务的间隔，不是网站功能。（10）
