## 1. 结论

**「体验友好」由好用、好懂、好看、可信、舒适、Agent 可用六个维度组成，共 58 条规则（§2、§4）。一个质量词只有在能判对错时才能用：它要有对标、从对标上观察到的特征、由特征推出的规则、适用范围、检查方法和门槛。** 验收里出现没定义的质量词，或者「适当」「尽量」这类判不了对错的虚词，检查不通过（`npm run check:vague`）。

## 2. 总树

### 2.1 六个维度和分界

按用户心里的六个问题分（第六个是替用户办事的 Agent 的问题），一个问题对应一个维度：

| 维度 | 用户的问题 | 管什么 | 收进来的词 | 规则 |
|---|---|---|---|---|
| 好用 | 我能不能快、顺地做成想做的事？ | 路径和操作：找得到、步数、反馈、速度、出错和失败、键盘、换设备姿态不打断 | 好用、易用、易上手、简单、一眼、直观、顺手、流畅 | U1–U13 |
| 好懂 | 我看不看得懂？ | 文字和信息：句子、段落、术语、按钮文字、不用读就会用、图表、结构、两种语言 | 易懂、易理解、通俗、白话、清楚、清晰 | C1–C10 |
| 好看 | 它看起来是不是用心做的、有自己的样子？ | 视觉秩序和身份：字体、颜色、版式、材质、动效的含义、排版细节、模板味 | 好看、美观、高级感、高级、有品味、品味、极简、简洁、克制、精致、质感、赏心悦目、干净、苹果设计语言 | V1–V10 |
| 可信 | 我信不信它说的？ | 出处、日期、更正、判断、健康内容、不操纵、只放正式版 | 专业、可信、有深度、有分量、值得读 | T1–T11 |
| 舒适 | 用着累不累、会不会被打扰？ | 感官和身体的负担：看得清、点得准、能缩放、不晕、不被打扰、读不累、媒体有替代、不被折痕挡住 | 舒服、舒适、不打扰、轻松、好读 | A1–A8 |
| Agent 可用 | Agent 替我办事时，它看得懂、点得到、复现得了吗？ | 给 Agent 的结构：语义和可读名称、状态在地址里、展开不靠悬停、正文不靠脚本、机器可读件、不用验证码挡人、机器流量分开统计 | 对 Agent 友好、Agent 友好、机器可读 | X1–X6 |

分界容易混的地方，按这几条判：

- 键盘能不能做完、焦点在哪里：属于**好用**（路径）。点按区域多大、对比度够不够：属于**舒适**（身体）。
- 动效有没有含义、是不是唯一的签名：属于**好看**。动效会不会让人晕、能不能停：属于**舒适**。
- 字号、行宽、行高：属于**舒适**（读不累）。中西文间距、标点、标题换行：属于**好看**（排版细节）。句子和段落多长：属于**好懂**。
- 文章怎么组织（问题 → 方案 → 总结、侧注、图表）：属于**好懂**。元信息里的日期和更新属于**可信**，其余放什么、不放什么属于**好看**（克制）。

### 2.2 组合词

- **体验友好**：六个维度里，适用于这一页的规则全部通过（X 组只在关口四查，之前的关口不算它）。
- **专业又通俗易懂**：可信（T）和好懂（C）同时通过。
- **拿奖级**：体验友好，再按 Awwwards 的权重评分：设计 40%、可用性 30%、创意 20%、内容 10%（[Awwwards 评审说明](https://www.awwwards.com/about-evaluation/)）。两份独立设计评审各打 1–10 分，加权平均都 ≥ 7.0、单项都 ≥ 6.5。6.5 是 Awwwards 荣誉提名的分数线（[FAQ](https://awwwards.com/faqs)）；7.0 是自定，留出余量；Awwwards 没有公布每日最佳的分数线（未查到）。四项对应标杆卡的原则：设计 → P2、P5；可用性 → P1；创意 → P4；内容 → P3（`docs/uiue/bar-sheet.md`）。
  拿奖级是上线后持续打磨的目标，不是上线门槛：关口四记录两份评审的加权分，不按它判通过；上线的设计门槛见 `pipeline.md` §2.3（需求第 102 条）。
- **极致**：拿奖级，同样是上线后的打磨目标，不是上线门槛。
- 不进检查的词：「一致」「统一」「完整」带了参照物就能判（「和术语表一致」「清单完整：逐条有着落」），所以不列进 §8；没有参照物时同样不能用。

## 3. 怎么定义一个词

1. **先问用户因为它能做成什么**：每个质量词都回到 PRD 的目标，说不出对用户的作用，这个词就不该出现。
2. **选对标**，四条都满足：做的是同一类任务或面向同一类读者；有公认的证据（获奖、被同行引用、行业规范）；页面公开、能直接观察；至少两个来源。只有一个来源的规则标「单一来源」，观察者优先补第二个。
3. **观察对标**：只记能观察到的特征（数得出、量得出、截得到图），每条附网址和查询日期。查不到的写「未查到」。
4. **推规则**：几个对标共有的特征才变成规则，一家的个例不算共性。每条规则写清适用范围、谁来查、门槛。
5. **对抗**：找反例，即满足了全部规则、用户仍然觉得不好的情况。找到就说明规则不完整，补一条。
6. **不重不漏**：一个词只归一个维度；同义词并进同一个条目；同一条规则只写在一个地方，别处引用编号。

### 4.7 用这些规则对照现有设计，发现的冲突

对抗评审的结果，交给关口三 a（#14）处理：

1. **英文正文太宽、行距太大**：正文版心 640px、16px 时，英文每行约 80–90 个字符，超过 A6 的 75；英文行高 1.7 超过 1.45 倍。中文 640px ÷ 16px = 40 字，正好在上限。英文版要单独定字号、版心或行高。**已定**（第 2 轮定的是英文 18px、版心 612px；2026-11-12 设计 v1.1 把字号阶梯收到 8 级以后改成现在的值）：英文正文 17px、行高 1.45（`leading-latin`）、版心 580px（`text-max-en`），每行约 68 个字符；中文正文 17px、行高 1.8、版心 640px，每行约 37 字（设计系统「字体和字号阶梯」）。
2. **首页「叶与网」一直在动**：不悬停时 10 秒一次呼吸，A4 要求能暂停。现在滚出视野会停，还缺一个暂停的方式。**已改（第 1 轮）**：首屏右上角加暂停按钮。
3. **语言切换的点按高度 38px**，小于 A2 的 44px（手机、平板画板）。**已改（第 1 轮）**：分段控件每项 44px。
4. **站稳、动手两块画板写死了 145 处颜色**，违反 V6。**已改（第 1 轮）**：两块画板重做，只用 token。

这一版改规则时和 PRD、设计系统对齐的地方（规则让步，不算设计的问题）：C4 放宽到 8 个字（「进入今天的训练」是 7 个字）；V1 改成设计系统的「字体三种」，首页看清一侧也用衬线；V2 改成设计系统的「三站，三种底色」；V3 按区域算，不按整个首屏；V7 区分首页和分站；V8 加上作者；A6 的英文行长统一为 `velicoach-layout` 的 60–75。

## 7. 怎么用

- 验收里用到 §8 的质量词：写上它所在维度的规则编号「quality-terms <规则编号>」（例如「首页好看：首屏每个区域只放标题、一句说明和操作，quality-terms V3」），或者直接把规则写进验收。编号必须真实存在，而且要和这个词属于同一个维度（「好看」要引 V 开头的规则），脚本会核对。
- 「体验友好」「拿奖」「极致」这类组合词，写「quality-terms §2.2」，或者拆成具体规则。
- 加了引号只对虚词有效（表示在提到这个词）；质量词加了引号照样要有定义。
- 检查范围：勾选项；标题含「验收」「完成标准」「出口」「退出条件」等字样的小节下的列表；表格里表头含「验收」「出口」「交付物」「怎么查」「门槛」「完成标准」等字样的列，以及表头就是「要求」的列（PRD 第 8 节的要求本身就是验收）。说明性的正文不查。
- 新的质量词：先按 §3 定义，加进 §2.1 的词表和 §8，再用。
