# 体验原则复核：结论和去处

> 2026-11-08。按需求第 78 条，研究了苹果、迪士尼、Vercel、Shopify、Anthropic、OpenAI，以及人与 Agent 友好的设计（AUI、AX），用研究结果逐条复核我们的体验原则。三份研究报告在本目录：`apple-disney.md`、`vercel-shopify-claude-openai.md`、`agent-ui.md`。可复用的结论写进了设计技能 `design-bar/references/ux-canon.md`。

## 结论

**我们的原则大多站得住；有四处要改，两类要补，一处要收紧。** 改的都是「把一个数当成目标」的地方：步数、1 秒、玻璃的透明度、悬停时间。补的是「人和 Agent」这一类，过去没有规则。

## 逐条判定

| 现有原则 | 判定 | 怎么改 | 依据 |
|---|---|---|---|
| 一键：核心两步、非核心三步，超预算就改设计、不改预算 | **改** | 每一步标「意图步」或「可删步」：意图步（同意、付款、不可逆、对外发送）不计入预算，也不许省；超预算只删可删步 | 苹果给 Apple Pay 有意加了一步确认；迪士尼把规划挪到入园前；Polaris「用摩擦突出重要决定」 |
| 一秒：每个操作 P95 ≤ 1 秒 | **改** | 拆两层：按下 0.1 秒内有回应（全部操作）；完成 P95 ≤ 1 秒只对不涉及生成的操作；生成类写清在做什么 | NN/g 响应时间三界限、WWDC18 Fluid Interfaces 说的「即时」是回应不是完成；HIG Generative AI |
| 超过 1 秒显示进度 | **补** | 进度写「动词 + 对象」，不写「加载中」；转圈延迟出现、出现后至少显示一会儿，不闪；超过 10 秒允许离开。画板检查加「笼统的进度文字」 | HIG Generative AI；Maister 等待心理学；Vercel |
| 能撤回的用撤销，不弹「确定吗」 | **补半句** | 撤不回的要一个确认意图的动作，写清后果，否则这条会被套到不可逆的操作上 | HIG；Anthropic 确认疲劳的数据；Vercel、Polaris |
| 玻璃要看得出背后的内容 | **改** | 实色是默认；玻璃先答「透过它看到的东西对读者有没有用」；「看得出背后」是门槛不是目标，阅读页默认厚一档；透镜是渐进增强，一屏最多两处，有性能预算 | HIG Delight「不要把装饰当惊喜」；苹果补了 Tinted 开关；Polaris、Vercel、OpenAI 都把装饰放在最后 |
| 原地展开：悬停 80ms | **收紧** | 80ms 标成自定，关口四测误触；选项始终在 DOM 里、是真链接，不悬停也能到达 | 没有一手来源支持 80ms；浏览器 Agent 读无障碍树 |
| 一站、不用读就会用、首屏是操作台、按钮直达结果 | 保留 | — | HIG Familiarity、Agency；迪士尼 wienie；Krug |
| 动效有含义 | **补** | 先过必要性检查；动画进行中输入立刻生效（可打断） | Vercel；WWDC18 |
| （没有）AI 内容的标识 | **新增 T11** | 合成旁白、AI 写的摘要或译文、Agent 排的计划都有看得见的标识；数字和安全判断由代码给出 | HIG Generative AI；微软 G1、G2 |
| （没有）Agent 能不能用我们的网站 | **新增维度 X1–X6** | 状态进地址、原生控件和可读名称、展开不靠悬停、正文不靠脚本、不用验证码挡人、机器流量分开统计 | 浏览器 Agent 先读无障碍树；web.dev；Google AI 搜索指南 |

**没有采纳的**：
- 「三次点击规则」：没有数据支持。
- 「零步」：苹果自己也不这么做。
- 迪士尼式的沉浸：工具类产品里会变成藏系统状态。
- 用 llms.txt、WebMCP 带流量：还是提案。
- Polaris 的「常用动作只用图标」：只适合每天用的后台。
- OpenAI Apps SDK 的「五条原则」：现行官方页面里已经没有了，不当出处。

## 冲突时的先后（新增）

安全、诚实和保真 → 人掌控 → 完成任务 → 看得懂 → 好看和惊喜。来自迪士尼 Four Keys、苹果 HIG 2026 版里 Responsibility 先于 Delight 的顺序，以及 Vercel design.md 把「保住给定的事实、单位和限定语」放在第一位。

## Vercel design.md 原文（2026-11-08 补读）

产品负责人给了 [vercel.com/design.md](https://vercel.com/design.md) 的地址，补读后：

- 它本身就是一份写给 Agent 的技能，范围是 Vercel 署名的报告页。
- 通用的四点进了 `ux-canon.md` §3.5「给 Agent 用的设计说明怎么写」：
  - 先后顺序写在最前面，保真第一；
  - 只在会改变含义的地方提问；
  - Agent 只用公开的 token 和类名；
  - 四遍做法，交成品不交日记。
- 三个反模式进了 `anti-patterns.md`：默认版式、重复摘要、过程旁白。
- 它的「不要玻璃、默认静止、不要庆祝」是报告页的口味，不当禁令。我们保留玻璃，但按「装饰要证明自己有用」收紧。

## 什么时候再复核

有人提出新的体验原则，或者对标产品发布新版规范时，按 `ux-canon.md` §5 第 4 条走：先判它和哪条重合、证据够不够、在哪不成立，再改规则。苹果 HIG 2026-06-08 的新版是这一次复核时才发现的，说明原则会过时，要定期查。
