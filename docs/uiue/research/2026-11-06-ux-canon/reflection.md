# 反思：这次借来的东西，有没有让产品离目标更近

> 2026-11-08。产品负责人的要求：研究只是参考，借的是机制和原理，用来补盲区；最后要回到产品期望的效果，结合 Agent 原生产品的特性判断有没有益处，不照抄、不做成四不像。

## 判断用的尺子

- **Veli 的目标**：让上班族把力量训练变成每周真的会发生的事。威利像总管，在用户想到之前把这一天安排好、把准备做完，用户只需要照做或到场。
- **Velicoach 的目标**：AGI 路上的陪练。先站稳、再看清、然后动手；读的人一来就知道给谁、做什么，看完能动手。
- **Agent 原生**：Agent 先动手，人看结果、改结果。界面主要是用来「看见和收回」的，不是用来「一步步操作」的。

一条借来的规则，过了三问才留：
1. 它要解决的问题，我们有没有？
2. 它的场景和我们一不一样？要看谁在用、多常用、是人做还是 Agent 做。
3. 加进来以后，离上面的目标更近还是更远？

## 这次自己犯的错

1. **把「人在操作的产品」的结论搬到了「Agent 在操作的产品」上。**「零步是神话」和「按类别授权」，都是在人亲手操作的界面里得出的，我没先问场景就写进了通用总纲。以后对标规则先过上面的三问，结论写进总纲第 7 节「参考不照抄」。
2. **没先读自己产品的现有设计。** Veli 工作手册里的自主等级、授权表、「今天替你做了 N 件」，比这次研究的结论更成熟。研究应该从「我们已经有什么」开始，再找盲区。
3. **规则在变多。** 规则表从 51 条涨到 58 条。以后新规则要替换或合并旧规则，规则总数不跟着研究一起涨。

## 授权：默认授权，少数场景确认（待产品负责人确认）

默认：Veli 和主站里的例行动作直接做，做完在「今天替你做了 N 件」里能看到、24 小时内能撤销，授权在「威利能做的事」里一处收回。

分三类：

1. **系统层面绕不开的**（不是我们加的确认）：
   - 手机系统的权限弹窗：健康数据、定位、麦克风、通知、相册；
   - Google、Apple 登录和日历的授权页；
   - 年龄确认。
2. **建议仍要确认的**：
   - 付款和续费扣费；
   - 把照片或数据发到云上、发给图像模型、分享给别人；
   - 删除账号和数据；
   - 改训练目标或加训练日（改变习惯）。
3. **建议从「先问」改成默认做、可撤销的**：
   - 把 Veli 的训练块写进日历；
   - 记住常用地点；
   - 跨层进阶；
   - 训练挪到截止时间之后。
   
   改成默认做以后，每次都在当天的清单里写明。

主站：订阅的邮件二次确认保留。它不是向用户要授权，是证明邮箱是本人的，能防垃圾订阅，也保证邮件能送到。
